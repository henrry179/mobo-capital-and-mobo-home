# 迁移与备份策略

> 原则：**结构变更走迁移，数据保护走备份；备份必须演练，演练必须留记录。**

## 1. 迁移机制

### 1.1 目录与命名

```text
migrations/
├─ README.md
├─ 202610200001__init_archive_assets.sql
├─ 202610200002__add_workout_tags.sql
└─ ...
```

- 文件名：`YYYYMMDDHHMM__short_description.sql`（双下划线）。
- 只允许向前迁移；回滚写在同一目录的 `*.rollback.sql` 或在文件头注释说明。
- 生产执行前先在 staging/本地空库演练。

### 1.2 版本表

```sql
CREATE TABLE IF NOT EXISTS public.schema_migrations (
    version     TEXT PRIMARY KEY,
    description TEXT NOT NULL,
    applied_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    checksum    TEXT NOT NULL
);
```

### 1.3 执行约定

1. 先 `pg_dump -Fc` 备份目标库。
2. 在事务中执行（`BEGIN; ... COMMIT;`）；`CREATE INDEX CONCURRENTLY` 例外，需单独步骤。
3. 执行后跑 Smoke Test：
   ```bash
   docker compose exec -T postgres psql -U postgres -d db_archive -f /docker-entrypoint-initdb.d/../smoke.sql
   ```
   实际 smoke SQL 在 `tests/sql/smoke.sql`，通过挂载或 `psql -f` 执行。
4. 记录迁移版本、耗时、异常到 `docs/05-运维与灾备/日常运维.md` 的变更日志。

### 1.4 破坏性变更

- 删列/改类型：先加新列 → 双写/回填 → 切读 → 再删旧列；至少跨一个发布周期。
- 改枚举：新增值可直接 `ALTER TYPE ... ADD VALUE`；删除值需重建类型，必须停机窗口。
- 改向量维度：新建 `vector(n)` 列 + 回填 + 重建 HNSW，不能原地改维度。
- 大表加索引：用 `CONCURRENTLY`，并设置 `maintenance_work_mem`。

## 2. 备份架构

```text
每日 03:00（容器时区）
  ├─ pg_dump -Fc db_mobobrain
  ├─ pg_dump -Fc db_archive
  ├─ pg_dumpall --globals-only
  ├─ 思源工作区 deploy/volumes/mobobrain_data
  ├─ n8n 数据 deploy/volumes/n8n_data
  └─ 配置 deploy/caddy、deploy/backup、initdb、docker-compose.yml
        ↓
  Restic 加密（AES-256）→ OSS 私有 Bucket restic-cold-backup/
        ↓
  保留：7 日 + 4 周 + 6 月；每周 check；每月抽查 5% 数据
```

### 2.1 为什么不直接备份 `pg_data`

运行中的 PostgreSQL 数据目录不是一致性快照；直接复制可能得到损坏的 WAL/数据文件。**数据库必须用 `pg_dump` 逻辑备份**。文件卷（思源/n8n）在容器运行中备份也有轻微不一致风险，但可接受；重要变更前先停写或手工快照。

### 2.2 备份目标

| 项 | 值 |
|---|---|
| RPO | 24 小时（每日备份） |
| RTO（数据库+配置） | ≤ 2 小时 |
| RTO（文件卷） | 4–24 小时，取决于 OSS 下载带宽 |
| 备份加密 | Restic 仓库密码 + OSS 服务端加密 |
| 备份保留 | 7 日 / 4 周 / 6 月 |
| 异地 | OSS 同地域；建议每季度导出一次到另一地域/本地冷盘 |

### 2.3 关键约束

- `RESTIC_PASSWORD`、`N8N_ENCRYPTION_KEY` **不在备份里**，必须存密码管理器；丢失后 n8n 凭证无法解密。
- `.env` 不进入 Restic（配置目录只挂载了 Caddy/备份/initdb/compose）；恢复时从密码管理器重建。
- OSS `restic-cold-backup/` 只转 IA，不转 Archive；Archive 取回会影响恢复时间与费用。
- 首次备份前先确认 Restic 仓库可写；不要把仓库密码写进脚本。

## 3. 日常备份操作

### 3.1 手工触发一次

```bash
docker compose exec -T restic-backup /usr/local/bin/run-daily-backup.sh
```

或临时容器：

```bash
docker compose run --rm restic-backup /usr/local/bin/run-daily-backup.sh
```

### 3.2 查看快照

```bash
docker compose exec -T restic-backup restic snapshots --latest 5
docker compose exec -T restic-backup restic stats
```

### 3.3 校验

```bash
# 元数据校验（快，每周）
docker compose exec -T restic-backup restic check

# 抽查 5% 数据（慢，每月）
docker compose exec -T restic-backup restic check --read-data-subset=5%
```

### 3.4 恢复单个文件

```bash
docker compose exec -T restic-backup restic restore latest \
  --target /tmp/restore --include /data/config/caddy/Caddyfile
docker compose cp restic-backup:/tmp/restore/data/config/caddy/Caddyfile ./Caddyfile.restored
```

## 4. 恢复演练（非破坏性）

脚本：[`deploy/backup/restore-drill.sh`](../../deploy/backup/restore-drill.sh)。

```bash
# 在服务器项目根目录，确保 127.0.0.1:5432 可连
./deploy/backup/restore-drill.sh

# 指定快照
RESTORE_TARGET=<snapshot-id> ./deploy/backup/restore-drill.sh
```

脚本会：

1. 从 Restic 恢复最新快照到 `drill-restore/`。
2. 创建 `db_mobobrain_drill` / `db_archive_drill`。
3. `pg_restore` 双库。
4. 对账核心表计数、触发器、周视图。
5. 删除演练库（失败时保留 staging 便于排查）。

**验收**：核心表计数与快照一致（允许生产增量差异）；触发器存在；周视图可查询；耗时记录到演练文档。

## 5. 灾难恢复（破坏性）

脚本：[`deploy/backup/disaster-recovery.sh`](../../deploy/backup/disaster-recovery.sh)。

```bash
# 1) 重装系统/安装 Docker/restic/postgresql-client
# 2) 从密码管理器恢复 /opt/mobo-stack/.env
# 3) 在项目根执行
CONFIRM_RESTORE=YES ./deploy/backup/disaster-recovery.sh
```

脚本阶段：

1. 安全门禁（必须 `CONFIRM_RESTORE=YES`、root、依赖命令）。
2. 选择快照并停止容器。
3. Restic 恢复到 staging。
4. 恢复思源/n8n 卷与配置（不恢复 `.env`）。
5. 单启 Postgres，DROP/重建双库，`pg_restore`。
6. 拉起全栈、对账、Smoke Test。

### 5.1 恢复后必查

- [ ] `https://archive...` 能登录，看板 4 模块有数据。
- [ ] `https://kb...` 思源文档/附件可打开。
- [ ] n8n 工作流、凭证、执行历史存在；`N8N_ENCRYPTION_KEY` 与备份时一致。
- [ ] `docker compose ps` 全部 healthy。
- [ ] `deploy/scripts/smoke-test.sh` 通过。
- [ ] 记录实际 RTO、数据缺口、异常。

### 5.2 常见恢复失败

| 现象 | 原因 | 处理 |
|---|---|---|
| `pg_restore: extension "vector" does not exist` | 目标库未装 pgvector | 确认镜像 `pgvector/pgvector:pg16`，先 `CREATE EXTENSION vector` |
| `role "user_archive" does not exist` | 未恢复 globals | 先执行 `01` 的角色部分，或 `RESTORE_GLOBALS=1` |
| n8n 登录后凭证报错 | 加密密钥不一致 | 从密码管理器恢复原 `N8N_ENCRYPTION_KEY` |
| 思源打不开 | 卷权限/版本不匹配 | `chown -R 1000:1000`；核对镜像版本 |
| Restic 下载极慢 | OSS 冷层/带宽 | 提前预热/提高带宽；不要转 Archive |

## 6. 备份检查清单

### 每日（自动）

- [ ] 03:00 备份任务成功（看 `docker logs mobo-restic-backup`）。
- [ ] 本地 staging 有当日 dump。
- [ ] Restic 快照数量正常。

### 每周

- [ ] `restic check` 通过。
- [ ] 磁盘使用 < 70%。
- [ ] 抽查一个文件可恢复。

### 每月

- [ ] `restic check --read-data-subset=5%`。
- [ ] 成本对账（OSS 请求/存储/流量）。
- [ ] 更新恢复演练记录。

### 每季度

- [ ] 完整恢复演练（非破坏性）。
- [ ] 核对 `.env` 与密码管理器一致。
- [ ] 检查 OSS 生命周期规则是否仍为 4 条。
