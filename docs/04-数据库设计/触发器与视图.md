# 触发器与视图说明

> 目标：让业务表写入后自动维护统一时间线，同时保持幂等、可回滚、可测试。

## 1. 触发器总览

| 触发器 | 表 | 时机 | 作用 |
|---|---|---|---|
| `trg_sync_reading_to_timeline` | `archive.reading_items` | AFTER INSERT/UPDATE/DELETE | 完读 → `BOOK_FINISHED`；回退状态/删除 → 清理节点 |
| `trg_refresh_reading_timeline_stats` | `archive.reading_logs` | AFTER INSERT/UPDATE/DELETE | 刷新已存在时间线节点的时长/笔记数 |
| `trg_sync_workout_to_timeline` | `archive.fitness_workouts` | AFTER INSERT/UPDATE/DELETE | 训练 → `WORKOUT_<TYPE>` |
| `trg_sync_retro_to_timeline` | `archive.project_retrospectives` | AFTER INSERT/UPDATE/DELETE | 复盘 → `RETRO_<TYPE>` |
| `trg_auto_calc_nav_on_trade` | `capital.trade_reviews` | AFTER INSERT/UPDATE | 平仓 → NAV / 高水位 / 业绩报酬 / 回撤熔断 |
| `trg_touch_updated_at_*` | `archive`/`intel`/`capital` 含 `updated_at` 的表 | BEFORE UPDATE | 统一刷新 `updated_at` |

### 1.1 阅读完读

- 仅 `status = 'COMPLETED'` 创建/更新节点。
- `occurred_at`：`started_at` 当天 09:00；没有则用 `finished_at` 20:00；再没有用 `NOW()`。
- `ended_at`：`finished_at` 当天 20:00；没有则 `NOW()`。
- `importance_score`：有评分按评分取整（1–10），否则 6。
- `duration_minutes`：所有 `SESSION` 日志时长之和。
- `metrics_payload.notes_count`：`HIGHLIGHT` + `THOUGHT` 数。
- 从 `COMPLETED` 改回其他状态：删除该来源的时间线节点。

### 1.2 阅读日志刷新

- 只在时间线节点已存在时更新，不主动创建。
- 插入日志后，重新汇总 `duration_minutes` 与 `notes_count`。
- 删除书目时日志级联删除；日志触发器找不到节点，安全返回。

### 1.3 运动

- `event_type = 'WORKOUT_' || UPPER(workout_type)`，如 `WORKOUT_RUNNING`。
- 标题：用户标题；否则按跑步距离/力量容量/类型自动生成。
- 重要性：距离 ≥ 15km、RPE ≥ 8.5 或时长 ≥ 90min → 7，否则 5。
- 能量影响：高强度 +3，否则 +2。
- 标签：同步 `NEW.tags` 到时间线。

### 1.4 复盘

- `occurred_at = period_start`；`ended_at = period_end + 23:59:59`。
- 摘要：优先拼接“原则迭代”和“偏差归因”。
- 重要性：`PROJECT_POSTMORTEM` / `TRADING_PLAYBOOK` / `EXAM_STAGE` → 8，否则 6。
- 能量影响：`execution_score - 5`，无评分默认 +1。
- 隐私、标签同步。

### 1.5 `updated_at`

- 在 `09-updated-at-triggers.sql` 中动态遍历 `archive`、`intel` 与 `capital` 三个 Schema 的含 `updated_at` 基表。
- 不处理 `n8n` Schema：n8n 自己的迁移管理。
- 新增表后重跑 `09` 才会自动挂触发器；生产通过迁移补充。

### 1.6 组合 NAV 与回撤熔断（`capital` 域）

触发器：`trg_auto_calc_nav_on_trade`（`AFTER INSERT OR UPDATE ON capital.trade_reviews`）。

- 仅当 `NEW.trade_status IN ('CLOSED','STOPPED_OUT')` 且 `NEW.portfolio_impact_bps IS NOT NULL` 时触发。
- 毛净值 `gross_nav = 1 + Σ(portfolio_impact_bps) / 10000`（基于全部已平仓交易）。
- 高水位 `high_water_mark = max(上一高水位, gross_nav)`。
- 业绩报酬 `(gross_nav - 1) × 20%`（仅盈利时计提），扣费后为 `net_nav`。
- 回撤 `(gross_nav - high_water_mark) / high_water_mark × 100`。
- 风控状态：
  - 回撤 > -5%：`NORMAL`（单笔风险 ≤ 1.50% NAV）；
  - 回撤 ≤ -5%：`YELLOW_ALERT`（单笔风险下调至 0.75% NAV）；
  - 回撤 ≤ -8%：`RED_CIRCUIT_BREAKER`（总敞口压降至 25% 以内，禁止新开买方期权头寸）。
- 写入 `capital.portfolio_nav_ledger`，按 `valuation_date` 唯一（重复则更新当天记录）。
- 触发器函数声明 `SET search_path = capital, public`，避免受调用会话影响。

> 阈值与费率集中在触发器函数内，调整必须走 migration 并同步更新
> [`莫伯资本数据字典.md`](莫伯资本数据字典.md) 与监控告警阈值。

## 2. 幂等与并发

- 时间线唯一键 `(source_table, source_id)`；触发器使用 `INSERT ... ON CONFLICT ... DO UPDATE`。
- 同一事务内先写业务表再写时间线；失败一起回滚。
- 不要在应用层再写一遍时间线；否则会出现双写/覆盖。
- 如果手工修复数据，优先修正来源表，再让触发器刷新；不要只改时间线。

## 3. 视图

### `archive.v_weekly_life_analytics`

- 用 `generate_series` 生成近 52 周，空周补 0（生理指标除外）。
- 周起始为周一（PostgreSQL `date_trunc('week')`）。
- 阅读/运动按 `started_at` 归周；复盘按 `period_end` 归周。
- 看板使用 `week_start ASC` 读取；SQL 视图本身 `DESC`，看板会再排序。

### `archive.v_asset_storage_summary`

- 按 `current_tier` + `asset_category` 汇总。
- 不包含软删除资产。
- `total_pretty` 是 PostgreSQL `pg_size_pretty`；看板会再格式化为更紧凑的单位。

### `archive.v_recent_timeline`

- 近 90 天，按时间倒序。
- 供操作台/看板快速读取；长期分析仍查 `timeline_events`。

### `intel.v_recent_high_value`

- 高分（≥7）且已评分/已同步的文章。
- 工作流 #1 的推送候选集；不含 `NEW`/`REJECTED`。

### `capital.v_strategy_performance_summary`

- 按策略聚合：平仓笔数、实际胜率、平均盈利 R、平均亏损 R、累计 R、平均纪律分。
- `LEFT JOIN` 保证无交易的策略也出现在表中（用于与目标值对照）。

### `capital.v_media_conversion_funnel`

- 只统计 `publish_status = 'PUBLISHED'` 的文章。
- 渠道维度聚合曝光/阅读/互动/净增粉丝/主站回流，并计算"每千阅读涨粉"。

### `capital.v_latest_macro_indicators` / `capital.v_latest_options_vol_surface`

- `DISTINCT ON (indicator_code)` / `DISTINCT ON (underlying_ticker)` 取每个对象最新一条。
- 供 `sites/mobocapital/data/terminal-snapshot.json` 与 `/terminal` 栏目使用。

## 4. 测试 SQL

```sql
-- 1) 触发器存在性
SELECT tgname FROM pg_trigger
WHERE tgrelid IN (
  'archive.reading_items'::regclass,
  'archive.reading_logs'::regclass,
  'archive.fitness_workouts'::regclass,
  'archive.project_retrospectives'::regclass
)
AND NOT tgisinternal
ORDER BY 1;

-- 2) 完读→时间线（事务内回滚）
BEGIN;
INSERT INTO archive.reading_items (title, status, domain, finished_at)
VALUES ('触发器测试书', 'COMPLETED', 'LEARNING_EXAM', CURRENT_DATE)
RETURNING item_id \gset
SELECT count(*) FROM archive.timeline_events
WHERE source_table='reading_items' AND source_id=:'item_id';
ROLLBACK;

-- 3) 运动→时间线
BEGIN;
INSERT INTO archive.fitness_workouts (workout_type, started_at, duration_minutes, distance_meters)
VALUES ('RUNNING', NOW(), 50, 10000)
RETURNING workout_id \gset
SELECT title, event_type, tags FROM archive.timeline_events
WHERE source_table='fitness_workouts' AND source_id=:'workout_id';
ROLLBACK;

-- 4) 周视图
SELECT * FROM archive.v_weekly_life_analytics ORDER BY week_start DESC LIMIT 5;
```

## 5. 已知限制

1. **中文全文检索**：`to_tsvector('simple', ...)` 不是中文分词；生产以 `pg_trgm` 标题模糊 + 应用侧 embedding 为主。
2. **时区**：触发器把 `DATE` 转 `TIMESTAMPTZ` 时使用数据库会话时区；容器已固定 `Asia/Shanghai`。跨时区访问时要在会话中 `SET TIME ZONE`。
3. **触发器不调用外部服务**：不生成 embedding、不推送思源；这些由 n8n/CLI 负责。
4. **时间线是派生数据**：可以从来源表重建；不要在时间线上做人工长期编辑，否则下次刷新会被覆盖。
5. **删除是硬删除**：业务表没有软删除；误删需从备份恢复。资产表用 `deleted_at`，但对象 GC 仍需人工确认。
