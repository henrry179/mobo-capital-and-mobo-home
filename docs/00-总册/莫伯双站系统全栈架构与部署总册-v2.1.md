### 1.2 三层“独立”

1. **网站独立**：不同主域、不同容器应用、不同数据库与 Schema、不同鉴权策略。
2. **数据独立**：两站分别导出备份；任一上层损坏均可从原始数据重建。
3. **资源按需独立**：初期共用一台 2C4G；重负载（视频/OCR/大模型）剥离至 OSS 或独立主机。

### 1.3 本期不做

  多用户 / 注册 / 评论 / UGC / 社区。
  自动发布到微信公众号、雪球、X（**只生成草稿，人工终审后由人点发布**；微信草稿箱直推属"推送到草稿箱"，仍需人工在公众号后台确认）。
  服务器端视频转码、完整 OCR、模型训练。
  多活 / Kubernetes / 商业 SaaS 化。
  基金募集、投顾、跟单等需要金融牌照的业务（见 `docs/06 合规与成本/证券与自媒体合规.md`）。

## 3. 总体架构

### 3.1 容器矩阵

| 容器 | 镜像 | 限额 | 职责 | 关键约束 |
|   |   |   :|   |   |
| `mobo caddy` | `caddy:2.9 alpine` | 80m | 双主域 HTTPS、静态分发、`/internal/*` 守卫 | JSON 访问日志落盘供 fail2ban |
| `mobo postgres` | `pgvector/pgvector:pg16` | 600m | 单实例双库四 Schema | `shared_buffers=128MB`，仅 127.0.0.1 暴露 |
| `mobobrain pkm` | `b3log/siyuan` | 400m | 投研母本与创作源头 | v3.8+ 需 `serve` 子命令；访问码 + BasicAuth 双层 |
| `mobobrain n8n` | `n8nio/n8n` | 512m | 工作流 #1 / #2 | `EXECUTIONS_PROCESS=main`；启动迁移期堆峰值约 300MB |
| `archive dashboard` | 自建 Streamlit | 200m | 生命体征 Z Score / Lead Lag 实验室 | 仅 numpy + pandas，禁 scipy/sklearn |
| `mobo restic backup` | 自建 | 150m | 每日加密备份 | 仓库密码不入备份 |

> 限额合计 **1.94GB**；本地（WSL2 全栈）实测常驻 **≈610MiB**（思源初始化工作区后约 267MiB），2C4G 云端目标 ≤1.3GB，宿主机另配 4GB Swap。

### 3.2 网络分层

```text
Internet ──80/443──▶ edge_net ──▶ Caddy ──▶ internal_net (internal:true) ──▶ 应用/数据库
                                                     │
                                                     └─▶ egress_net ──▶ OSS / LLM / RSS
```

  只有 Caddy 暴露公网端口；5432 / 6806 / 5678 / 8501 不出公网。
  `internal_net` 为 `internal: true`，无默认网关。
  仅 n8n、看板、备份容器加入 `egress_net`。

### 3.3 端到端数据流

```text
RSS/URL ──▶ n8n #1 ──▶ Jina 提纯 ──▶ LLM 评分(≥7) ──▶ 思源笔记(母本)
                                                        │
                                     n8n #2 ◀── 人工发起/审阅
                                        │  单次 LLM 合成 → JSON(4 端)
                                        ├─▶ capital_publications(PENDING_REVIEW)
                                        └─(人工批准)─▶ 微信草稿箱 / X 串推 / 静态站落盘
                                                        │
                          CLI(mobo cli) ◀── 思源/数据库 ──▶ public data.json（物理脱敏）
                                                        └─▶ internal data.json（BasicAuth）
```

## 5. 自动化与内容流水线

> **决策**：n8n 子域与 `n8n` Schema 见 [ADR-0003](../01-项目治理/决策记录/ADR-0003-n8n子域与数据Schema.md)。

### 5.1 工作流 #1：情报提纯归档（`MoBoBrain_RSS_LLM_Archiver`）

1. 每 6 小时触发（或手动），读取 RSS 源；
2. `SplitInBatches(Batch=1)` 串行处理，避免 350MB 内存红线被击穿；
3. 计算 URL SHA 256，在 `intel.articles_vault` 查重；
4. 通过 `https://r.jina.ai/{url}` 提纯 Markdown 正文；
5. LLM 按 ITPM 相关性打分 1–10；
6. 评分 ≥ 7 的情报经思源内网 API `http://mobobrain pkm:6806/api/filetree/createDocWithMd` 写入母本，并回填 `siyuan_doc_id`。

### 5.2 工作流 #2：“1+3”四端同源合成与发布（`MoBoCapital_1Plus3_Synthesizer_Publisher`）

**阶段一 · 合成预审**（Webhook `/webhook/mobocapital synthesize`）：

  拉取思源母本 + 注入 `capital` 域历史上下文；
  **单次** LLM 调用（温度 0.3）输出严格 JSON：`slug`、`web_markdown`、`wechat_html`、`xueqiu_markdown`、`x_thread_json`；
  写入 `capital.capital_publications`，状态 `PENDING_REVIEW`，并通知本人审阅。

**阶段二 · 确认发布**（Webhook `/webhook/mobocapital publish`）：

  人工批准后：母本落盘到 `sites/mobocapital/`；
  微信：调用 `cgi bin/draft/add` 推入订阅号助手**草稿箱**（`content_source_url` 指向官网 memo 页）；
  X：Code 节点循环调用 X API v2，以 `in_reply_to_tweet_id` 链式串推（`workflows/nodes/x thread publish.code.js`）；
  回写线上链接（`wechat_draft_media_id`、`xueqiu_post_url`、`x_root_tweet_id`）。

### 5.3 提示词资产

`workflows/prompts/mobo capital synthesis prompt.md` 为四端合成 System Prompt：输出 slug 与四个终端版本；境内版本（微信/雪球）强制脱敏具体买卖点位、附合规免责声明；X 版本为 5–7 条 260 字符内的英文/双语串推。

### 5.4 人工终审闸门（HITL Gate）

> **决策**：公私域物理脱敏与 HITL 状态机见 [ADR-0009](../01-项目治理/决策记录/ADR-0009-公私域物理脱敏与HITL发布闸门.md)。

  工作流 **不得**直接置为 `PUBLISHED`；
  发布动作必须在 `capital_publications` 状态机中经历 `PENDING_REVIEW → APPROVED → PUBLISHED`；
  每次状态跃迁写 `intel.ingestion_runs`（`workflow_name`、`status`、`stats`）以便审计。

### 7.3 备份与灾备

> **决策**：备份保留与 RPO/RTO 见 [ADR-0004](../01-项目治理/决策记录/ADR-0004-备份与灾备.md)。操作脚本以 `deploy/backup/` 为准。

  每日 03:00：双库 `pg_dump  Fc` + `pg_dumpall   globals only` + 思源/n8n 卷 + 配置目录 → Restic 加密 → OSS `restic cold backup/`。
  保留：7 日 + 4 周 + 6 月；每周 `restic check`，每月 `  read data subset=5%`。
  灾备：`deploy/backup/disaster recovery.sh`（六阶段，支持 `  dry run` 就绪度校验）、`restore drill.sh`（非破坏性演练）。
  备份**不含** `.env`；`RESTIC_PASSWORD`、`N8N_ENCRYPTION_KEY` 只存密码管理器。

### 7.4 监控与巡检

  阿里云云监控（CPU/内存/磁盘/流量）、UptimeRobot（6 个入口）、Caddy 日志 401 暴破告警。
  `deploy/scripts/mobo_watchdog.sh`：每 15 分钟巡检内存/磁盘/容器健康，异常推飞书 Webhook。
  业务告警：NAV 回撤进入黄/红区、采集连续失败、LLM 日成本异常、备份超 26h 无新快照。

## 10. 验收标准

**功能**：六容器 healthy；双主域 HTTPS 绿锁；`/internal/*` 未认证 401；看板四模块有数据；CLI 五类录入 + `export site` 产出脱敏 JSON；n8n 两工作流端到端跑通。

**非功能**：总内存 < 1.55GB；无 OOM；备份可恢复、RTO ≤ 2h（DB/配置）；公域包脱敏审计 0 违规；`.env` 未入 Git；SSH 密钥登录 + UFW 仅 22/80/443。

**成本**：首年基础设施支出 ≤ 2,400 元并保留 ≥ 500 元机动；LLM 单独限额并按月对账。
