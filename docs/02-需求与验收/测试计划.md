# 测试计划

## 1. 测试层级

| 层级 | 范围 | 工具 | 频率 |
|---|---|---|---|
| 静态检查 | YAML/Shell/Python/SQL 语法 | `docker compose config`、`shellcheck`、`ruff`、`psql -f` | 每次提交 |
| 单元测试 | CLI 解析/哈希/缩略图/统计函数 | `pytest` | 每次提交 |
| SQL Smoke | 表/触发器/视图/权限 | `psql` + `tests/sql/smoke.sql` | 每次迁移 |
| 集成测试 | Postgres + CLI + 看板 | Docker Compose | 每次发布 |
| 端到端 | n8n → 思源 → 草稿 | 手工/脚本 | 每次发布 |
| 安全测试 | 401/头/端口/密钥 | `curl`、`ss`、`git` | 上线前 |
| 恢复演练 | Restic → staging → 对账 | `restore-drill.sh` | 每季度 |

## 2. 测试环境

### 本地

- Windows Docker Desktop / Linux Docker Engine。
- `.env` 使用本地值；域名可用 `localhost` 或 `*.local`。
- 无 OSS 时：只启动 `postgres` + `archive-dashboard`，看板走沙盒。
- 有 MinIO 时：验证 S3 路径/签名（可选）。

### 生产

- 阿里云 2C4G；OSS 同地域；真实域名/证书。
- 只做冒烟、恢复演练、安全验证；不做破坏性测试。

## 4. 缺陷分级

| 级别 | 定义 | 处理 |
|---|---|---|
| P0 | 数据丢失/安全失守/双站不可用 | 立即停发布，修复后回归 |
| P1 | 核心功能不可用/备份失败 | 24h 内修复 |
| P2 | 非核心功能/体验问题 | 下个迭代 |
| P3 | 文档/文案/优化 | 排期 |
