# 需求规格说明书

> 优先级：P0 = MVP 必须；P1 = 上线后 2–4 周；P2 = 按需。  
> 需求 ID 用于测试与验收追溯。

## 1. 用户与场景

### 1.1 用户

- **莫伯（唯一用户）**：内容研究、知识管理、个人档案、数据分析、系统运维。
- **公开访客**：只读网站 A 的公开专栏，不可访问知识库后台。
- **外部服务**：LLM/Embedding API、OSS、内容平台（人工发布）。

### 1.2 核心场景

1. 早上用 CLI 录入睡眠/静息心率；晚上录入跑步或力量训练。
2. 读完一本书，CLI 标记完成，时间线自动出现事件。
3. 周末写 Markdown 复盘，CLI 解析入库，触发时间线。
4. n8n 每 4 小时抓取 RSS，去重、评分、入库；高分文章推送思源。
5. 在思源/操作台选素材，生成三平台草稿，人工审核发布。
6. 打开看板，看周度阅读/运动/睡眠、Lead-Lag、资产总账。
7. 每月检查备份、成本、日志；每季度做恢复演练。

## 5. 数据需求

- 所有时间统一 `TIMESTAMPTZ`；日期用 `DATE`；周期用 `TSTZRANGE`。
- 所有业务表有主键、`created_at`；需要更新的表有 `updated_at`。
- 资产用 SHA-256 唯一；同一文件多引用时不重复存对象。
- 隐私等级：`PUBLIC/RESTRICTED/PRIVATE/VAULT`；`VAULT` 需应用层加密或额外保护。
- 删除采用软删除（资产）或触发器清理时间线；不做物理删除除非确认。
- 备份保留：日 7、周 4、月 6。
