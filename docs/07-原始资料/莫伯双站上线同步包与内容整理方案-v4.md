## 0. 一句话结论

**不要把 8.7 GB 原始文件夹直接 rsync 到 ECS。**  
按你的排除项，剩余 **8.73 GB / 29,751 文件**；其中真正需要进服务器“热区”的加工制品只有 **约 0.25–0.4 GB**，其余约 7.3 GB 是 People 存档、课件 PDF/Word 原件与压缩包，应放 **OSS 私有桶 / 本地冷存**，服务器只保留索引与缩略图。

> **“统一上传”应定义为：统一盘点 → 统一加工 → 统一打包 → 统一校验 → 统一发布 → 统一回滚。**  
> 不是“把源目录整包拷进 /opt/mobo-stack”。

## 2. 核心原则：服务器收“制品”，不收“原料”

### 2.1 三层职责

```text
本地原料（Word/PDF/图片/People/压缩包）
        │  ① 加工：转换、压缩、脱敏、去重、归一化
        ▼
发布制品（MD/HTML/JSON/WebP/索引）
        │  ② 打包：A/B × public/internal，MANIFEST + SHA256
        ▼
网站服务器（ECS 热区，约 0.25–0.4 GB）
        │  ③ 只读分发；原件走 OSS 私有桶 / 本地冷存
        ▼
用户浏览器（公开页只加载缩略图与 JSON）
```

### 2.2 五条硬规则

1. **源目录不直传**：`01-工作与项目/`、`hermes-migration/` 不整体 rsync 到服务器。
2. **原件与展示分离**：Word/PDF/图片原件进 `cold/` 或 OSS；服务器只放转换后的 MD/JSON/WebP。
3. **内容寻址命名**：媒体文件名用 `sha256[:16].webp`，追加不覆盖；JSON 用原子 `mv` 切换。
4. **公私域物理分离**：`public/` 与 `internal/` 两个发布包；`internal` 目录由 Caddy BasicAuth 保护。
5. **可回滚**：保留上一版 JSON + MANIFEST；媒体只增不删；DB 导入前有快照。

## 3. 逐类加工规则

### 3.1 Word（742 份 / 0.684 GB）

| 项 | 规则 |
|---|---|
| 转换 | `.docx` → Markdown（Pandoc）；复杂表格 → Markdown 表或 CSV；图片抽到 `media/` |
| 元数据 | 文首 YAML：`id/title/site/section/visibility/date/tags/source/license/hitl` |
| 去重 | 与 `01-MD` 同主题的 Word 标 `canonical=no`，不重复发布 |
| 原件 | 保留在 `cold/word/` 或 OSS；服务器只放转换后的 MD/HTML |
| 例外 | 662 份精读 Word 是衍生物；36 份大课件 Word 是原件；两者都不直接进公域 |

**不上传**：`~$*`、`._*`、`Workplace_v1_2` 之类版本堆叠；只保留最终版。

### 3.2 PDF（301 份 / 2.316 GB）

| 项 | 规则 |
|---|---|
| 文本 | `pdftotext` 抽文本；扫描件 OCR；产物进 `content/` 或数据库 |
| 封面 | 首页渲染 800px WebP，进 `media/covers/` |
| 元数据 | 标题/作者/页数/分类/版权标记进 `pdf-index.csv` |
| 原件 | 课件/研报原件进 OSS `scan_doc/` 冷存；**不在公网直链** |
| 公域 | 只有确认可公开的研报才生成脱敏 PDF；ITPM 课件一律 INTERNAL |

### 3.3 图片（14,036 张 / 4.990 GB）

| 集合 | 处理 | 服务器 |
|---|---|---|
| A 站封面 892 张 | 3 档 WebP：320 / 800 / 1600；去 EXIF；内容哈希命名 | `sites/mobocapital/media/` |
| B 站阅读封面 2 张 | 800px WebP | `sites/mobohome/media/` |
| People 剧照 10,930 张 | 只生成片页封面/精选缩略图；原图 OSS 私有 | ECS 只放缩略图 |
| 职场输出图 1,013 张 | 默认 PRIVATE；只留精选 | `internal/` |
| 精读内嵌图 409 张 | 按文章引用抽取；压缩后随文 | `media/inline/` |
| 字体 5 个 | 授权未核，禁止上传/渲染 | 不上传 |

**统一规则**：长边不超过 1600px；列表用 480px；WebP quality 78–82；单图 ≤200KB（封面 ≤60KB）；剥离 GPS/相机/作者 EXIF。

### 3.4 Markdown（9,162 份 / 0.094 GB）

- 统一 UTF-8、LF、YAML 头、slug、日期、track、站点、可见性。
- 标题/摘要/正文两级去重；同题只留 canonical。
- 相对链接改为 `/media/...` 或站内绝对路径；断链清单为 0 才发布。
- 只选精选，不做 9k 全量导入；People 的 7,882 份 MD 只作存档，不全部上站。

### 3.5 压缩包 / 表格 / 代码 / 其他

| 类型 | 规则 |
|---|---|
| 压缩包 18 / 0.444 GB | 不直传；先列出内容，抽取有价值文件，原包冷存 |
| 演示/表格 62 / 0.043 GB | `.xlsx` 转 CSV/JSON 用于公开数据；原始表格进 PRIVATE |
| 代码 2,962 / 0.045 GB | 工程仓 Git 部署；Hermes skills 不进入站点 |
| 字体 5 / 0.065 GB | 授权未核，暂不进任何发布包 |
| 其他 2,217 / 0.049 GB | 先分类；临时/系统文件进 quarantine |

## 5. 上传流水线（六步）

### S1 · 归类冻结

- 以 `launch-packages.csv` 为准，冻结本次版本目录与文件清单。
- 重新跑一次 SHA-256；写入 `MANIFEST.csv`。
- 先处理 8 处明文凭据（见 v3 §11.1），确保发布包内 0 密钥。

### S2 · 转换清洗

- Word → MD/HTML；PDF → 文本 + 封面；表格 → CSV/JSON。
- 统一 YAML、slug、标题、日期、tags、`site/visibility`。
- 去重：以 `duplicates.csv` 的 canonical 为准；同题只留一份。

### S3 · 媒体加工

- 三档 WebP：`thumb` 320 / `card` 800 / `hero` 1600。
- 去 EXIF；内容哈希命名；生成 `alt` 文本。
- 原图/原 PDF 不删除，只登记 `cold_path` 或 `planned_oss_key`。

### S4 · 构建与校验

```bash
python tools/content-build/build_release.py --site capital --date 2026-11-01
python tools/content-build/validate_release.py release/2026-11-01/capital
```

校验项：

- `public-data.json` / `public-home-data.json` 可 `jq` 解析；0 私有字段、0 INTERNAL。
- 每个 `media` 引用都存在；每张图 ≤ 上限；无 EXIF GPS。
- 0 断链；0 重复 slug；0 明文密钥；0 个人敏感信息。
- `MANIFEST.csv` 行数 = 文件数；`SHA256SUMS` 校验通过。

### S5 · 上传与原子切换

```bash
# 1) 先传内容寻址媒体：只增不删
rsync -avz --checksum release/2026-11-01/capital/public/media/ \
  mobo@server:/opt/mobo-stack/sites/mobocapital/media/

# 2) 传正文
rsync -avz --checksum release/2026-11-01/capital/public/content/ \
  mobo@server:/opt/mobo-stack/sites/mobocapital/content/

# 3) JSON 先传 .new，再原子 mv
scp release/2026-11-01/capital/public/data/public-data.json \
  mobo@server:/opt/mobo-stack/sites/mobocapital/data/public-data.json.new

ssh mobo@server '
  cd /opt/mobo-stack/sites/mobocapital/data &&
  cp -a public-data.json history/public-data-$(date +%Y%m%d).json 2>/dev/null || true &&
  mv public-data.json public-data.json.prev &&
  mv public-data.json.new public-data.json
'
```

> 不用 `rsync --delete` 对 `media/`；媒体是内容寻址，只增不删。  
> `internal/` 单独上传，权限 640/750；不放入公开 `media/`。

### S6 · 冒烟与回滚

```bash
curl -fsS https://mobocapital.com/data/public-data.json | jq empty
curl -fsS -o /dev/null -w '%{http_code}' https://mobocapital.com/
curl -fsS -o /dev/null -w '%{http_code}' https://mobocapital.com/internal/internal-data.json   # 期望 401
curl -fsS -o /dev/null -w '%{http_code}' https://mobocapital.com/media/thumbnails/<hash>.webp
```

回滚：

```bash
ssh mobo@server '
  cd /opt/mobo-stack/sites/mobocapital/data &&
  mv public-data.json public-data.json.failed &&
  mv public-data.json.prev public-data.json
'
```

- 媒体只增不删，回滚不需要动媒体。
- DB 导入前 `pg_dump`；回滚时恢复上一版 JSON + DB 快照。
- 保留最近 3 个发布版本；`history/` 只留 JSON，媒体按哈希长期保留。

## 6. 数据库与 JSON 的同步顺序

```text
① 本地内容加工 → ② MANIFEST/校验 → ③ DB 迁移/导入 → ④ 导出 public-data.json
   → ⑤ 上传 media/content → ⑥ 原子切换 JSON → ⑦ 冒烟 → ⑧ HITL 放行
```

- **先 DB 后 JSON**：`public-data.json` 必须来自已入库、已审核的数据。
- **不要反向**：不要先在服务器改 JSON，再回写数据库。
- **A/B 分库**：`db_mobobrain` / `db_archive` 各自导入；不跨库。
- **公开 JSON 脱敏**：继续使用 `exporters.audit_payload`；0 私有字段 / 0 INTERNAL。

## 7. 容量、拓扑与两种落盘方案

### 7.1 推荐拓扑（单 ECS 双站 + OSS）

| 层 | 放什么 | 体量 |
|---|---|---:|
| ECS `/opt/mobo-stack/sites` | 站点壳 + JSON + MD + 缩略图 | **0.25–0.4 GB** |
| ECS PostgreSQL | 结构化内容/索引 | 现有 DB |
| OSS 私有桶 | PDF/Word/图片原件、People 剧照 | **约 7.3 GB** |
| 本地金库 | 权威原件 + 备份 | 全量 |

**优点**：2C4G 磁盘/备份压力最小；公网只加载缩略图；OSS 内网免流。
**前提**：OSS 桶可用；服务器能访问内网 endpoint。

### 7.2 如果暂时没有 OSS

| 方案 | 服务器 | 体量 | 代价 |
|---|---|---:|---|
| A（推荐） | 只放热包；原件留本地 | 0.3 GB | 公网无法直链原件；后期再补 OSS |
| B（可接受） | 热包 + 私有原件 `/private/`（不公开） | 8.73 GB | 需要 ≥40 GB 磁盘；备份/迁移变重 |
| C（不推荐） | 全部原件 + 公开目录 | 8.73 GB | 版权/隐私/备份风险高 |

> **B 方案也可以做**：把 `People-archive` 与 `99-原始归档` 放 `/opt/mobo-stack/private/`，Caddy 不挂载该目录，只允许 SSH/运维访问；每日备份只备份元数据与 JSON，原件单独冷备。  
> 但 2C4G 单机更推荐 A 方案。

### 7.3 服务器磁盘检查

上线前在服务器执行：

```bash
df -h /opt/mobo-stack
du -sh /opt/mobo-stack/sites /opt/mobo-stack/deploy/volumes
```

建议：

- 内容热区 ≤ 磁盘的 20%；
- 保留 ≥ 20% 空闲；
- 若系统盘 40 GB，B 方案 8.73 GB 会明显压缩备份/日志空间，优先 A。

### 7.4 两个网站是一台还是两台？

当前架构是 **同一台 2C4G ECS 承载两个站点**（`docker-compose.yml` 六容器、双域 Caddy）。  
如果你确实要“两个网站服务器”，发布包可以完全独立，但需要：

- 两套 DB / 备份 / Caddy / 证书；
- 双倍内存与运维成本；
- 跨站链接用绝对域名；
- 不能共享 `/internal` 会话与 OSS 内网 endpoint 配置。

**建议**：仍按单机双站；逻辑上两个 release 包，物理上一台服务器。

## 8. 安全与合规（发布包必须过）

| # | 检查 | 标准 |
|---|---|---|
| 1 | 明文凭据 | 0 个 `.env`/密码/token/App Secret |
