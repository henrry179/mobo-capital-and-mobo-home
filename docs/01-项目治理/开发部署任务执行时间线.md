## 0. 执行规则

### 0.1 每日节奏（业余 4–6 小时）

| 时段 | 时长 | 角色 | 内容 |
|---|---:|---|---|
| 上午 | 1.5–2h | 人工 | 决策与内容：内容审阅、密钥准备、ADR 拍板、选题与素材 |
| 下午 | 2–3h | AI 智能体 | 执行：编码、配置、脚本、文档、联调、跑测试 |
| 晚上 | 0.5–1h | 人工 + AI | 验收：跑验收命令、看页面、勾自检清单、记录异常与提交 |

> 铁律：**AI 不自行决定对外可见内容与密钥**；**人工不手改代码**，只改配置与内容。

### 0.2 三类工时分配（本地阶段 5 天估算）

| 类别 | 占比 | 内容 |
|---|---:|---|
| 功能开发 | 45% | CLI/看板/工作流/门户的增量能力 |
| 联调与验证 | 30% | 端到端跑通、缺陷定位、性能与内存实测 |
| 文档与合规 | 15% | ADR、字典、清单、证据留痕 |
| 运维与备份 | 10% | 备份、演练、监控、巡检 |

### 0.4 AI 智能体分工（对应 `CLAUDE.md`）

| 角色 | 本阶段主责 | 交付物 |
|---|---|---|
| Claude Code CLI（架构与运维） | 编排/网关/SQL 注入与授权、备份演练、环境脚本 | `deploy/`、`docker-compose*.yml`、`tools/wsl/` |
| Codex CLI（工具链与审计） | CLI 增强、采集器、脱敏导出与审计、n8n 工作流 | `services/mobo-cli/`、`workflows/`、`exporters` 单测 |
| Cursor（前端与可视化） | 双站门户、看板界面、数据绑定 | `sites/`、`services/archive-dashboard/` |
| 人工（莫伯） | 内容审阅、密钥、ADR 拍板、发布批准 | ADR、密钥清单、发布确认 |

### 0.5 每日固定动作（本地阶段）

```bash
# 启动（会自动清理残留容器，避免静态 IP / 网络端点冲突）
cd /mnt/e/01-文档资料/报告与规划/莫伯双站系统 && bash tools/wsl/wsl-up.sh

# 停止
docker compose -f docker-compose.yml -f docker-compose.wsl.yml --env-file .env.local down

# 健康速查
docker compose -f docker-compose.yml -f docker-compose.wsl.yml --env-file .env.local ps
```

> 命令行测试若本机配置了 `http_proxy`，一律加 `--noproxy '*'`（否则会拿到代理返回的 502）。

### 0.6 每日收尾三件事

1. 跑当天的验收命令，勾自检清单，存证据到 `docs/05-运维与灾备/证据/YYYYMMDD-本地自检/`
2. 更新 `TASK_STATE.md` 状态 + 异常登记
3. 提交一次（ Conventional Commits），工作区保持干净

**D0 实际解决的真问题（已固化为基线，后续不再踩）**

| # | 问题 | 根因 | 固化方式 |
|---|---|---|---|
| 1 | WSL 里无 Docker | Windows 无管理员权限 | Docker Engine 装在 WSL2（`wsl -u root`），新增 `tools/wsl/` |
| 2 | 镜像拉取超时 | 代理 TLS 握手失败 + DNS 污染 | `daemon.json` 配 registry-mirrors（daocloud/1panel/rat.dev） |
| 3 | pip 安装超时 | pypi.org 不可达 | Dockerfile 增 `PIP_INDEX_URL` build arg，WSL 覆盖用清华源 |
| 4 | apk 安装失败 | Alpine 官方 CDN 被拦 | Dockerfile 增 `APK_MIRROR` build arg |
| 5 | Postgres 反复重启 | 绑定挂载在 /mnt/e（drvfs 不支持 chmod）+ 挂载点非空 | 命名卷 + `PGDATA` 子目录 |
| 6 | 思源容器退出 | v3.8 内核改为 CLI，需 `serve` 子命令 | compose 改为 `serve --accessAuthCode --port` |
| 7 | n8n 启动失败 | 缺库级 CREATE 权限（ACL 检查早于 IF NOT EXISTS） | 初始化脚本授权 + 迁移 `202610210001` |
| 8 | n8n 堆 OOM | `--max-old-space-size` 与 cgroup 限额不匹配 | n8n 限额 512m / 堆 400MB |
| 9 | 应用账号无权访问自己的表 | 01–07 由 postgres 建表，属主是 postgres，**未给业务账号授权** | `08-indexes-grants.sql` 补属主读写授权 + 默认权限 |
| 10 | CLI 读取返回值崩溃 | 游标是元组模式，`dict(row)` 抛 ValueError | 全部改用 `RealDictCursor`；`record_trade` 取值改 `.get("id")` |
| 11 | 静态 IP "Address already in use" | 已退出容器仍占用网络端点 | 重建前 `compose rm -sf` + `network prune`；启动脚本已内置清理 |
| 12 | **宿主机 CLI 连不上库** | postgres 只挂 `internal_net`，Docker 不为 internal 网络做端口 DNAT，`ports: 127.0.0.1:5432` 实际不通 | postgres 同时挂 `egress_net`（**基础编排同源缺陷，生产同样受影响**），CLI 固定走 `127.0.0.1` |
| 13 | 命令行 502 误判为网关故障 | 本机 `http_proxy=127.0.0.1:7897` 截走了请求（响应头带 `Proxy-Connection`） | 统一 `--noproxy '*'`；识别特征：502 且带 `Proxy-Connection` |
| 14 | 行动项解析把 due 吞进 owner | `owner: 我 due: 周日` 的取值只到分号 | `retro.parse_action_items` 改为按**已知键**切段（已加单测） |
| 15 | README 34 条文档链接 404 | 路径写成 `docs/01 项目治理`（空格）而非 `docs/01-项目治理` | 已批量修复并纳入质量门（Q14 链接 0 断链） |

## 5. 关键路径与并行关系

```text
人工决策链：域名 ─→ ICP ─→ 切流 ─→ 验收
                │                ↑
AI 执行链：  本地 D1→D5  ────────┘（云端复用同一套 compose 与 SQL）
```

- **人工瓶颈**：域名、ICP、密钥、内容审阅、发布批准 → 5 条串行、不可并行。
- **AI 可并行**：本地开发、联调、测试、文档、演练 → 5 天可压缩到 3 天。
- **不要做的事**（会破坏时间线）：
  - 在 ICP 未通过前切正式域名（合规风险）
  - 在备份未恢复成功前上线（数据风险）
  - 在 L5 质量门未过前上云（工程风险）
  - 在 HITL 未确认前启用微信/X 直发（合规风险）

## 6. 缓冲与应急

| 情形 | 缓冲策略 | 决策点 |
|---|---|---|
| 本地阶段某天受阻 | 顺延，优先保 D1/D2（数据与闭环） | 当晚评估是否砍 D3/D4 |
| 域名审核超期 | 本地阶段照常推进；公网线整体顺延，不压缩 T0+1~T0+4 | T0+3 顺延 >3 天则重排 |
| 出现 P1 缺陷 | 冻结新功能，当日修复 + 回归 | 次日评估是否影响 D5 |
| 内存超红线 | 降 n8n 并发/缩短执行上下文/裁剪看板依赖 | 触发红线一复核 |
| LLM 成本异常 | 降模型、截断输入、暂停非核心工作流 | 单日 > ¥30 触发 |

### 8.2 追踪规则

1. 本文是**时间维**（何时做、做多久、谁做），`里程碑与WBS.md` 是**任务维**（做什么），`TASK_STATE.md` 是**状态维**（做到哪）。
2. 任何任务延期 → 当日更新三份文档，并在 `TASK_STATE.md` §4 阻塞项登记。
3. 每日结束必须有：一条提交 + 一条证据 + 一次自检勾选。
4. 阶段收口必须写复盘：本周踩坑、根因、固化方式（今天 D0 的 15 个问题就是这个格式的样板）。
5. **质量门是硬闸门**：Q0–Q14 任一 FAIL，该阶段不得收口（判定脚本见 `tools/wsl/README.md` 与自检清单 L5）。
