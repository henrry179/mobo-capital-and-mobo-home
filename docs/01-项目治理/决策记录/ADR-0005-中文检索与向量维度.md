# ADR-0005：中文检索与向量维度

- 状态：Accepted（Embedding 维度待最终确认）
- 日期：2026-10-20
- 决策人：莫伯

> **Canonical**：本议题「为何如此」以本文为真源；总册 / docs/03 / 整合总览仅保留结论指针，勿复制背景/替代方案/后果长文。

## 背景

v1.0 使用 `to_tsvector('simple', ...)` 做全文检索，但 PostgreSQL 默认解析器不对中文分词，中文搜索效果很差。同时 `vector(1536)` 写死为 OpenAI 维度，换国产 Embedding 会写入失败；DDL 也没有 HNSW 索引。

## 决策

### 中文检索

1. **标题/摘要**：`pg_trgm` GIN + `ILIKE`，保证“关键词子串”可搜。
2. **正文全文**：应用侧（CLI/n8n）用 jieba 分词，写入 `search_vector`；不在数据库内做中文分词。
3. **语义检索**：pgvector + HNSW，作为主检索能力。
4. **zhparser**：作为后续可选增强；需要自定义 PostgreSQL 镜像，本期不默认启用。
5. 保留 `search_vector` 列，但明确其英文/分词后文本的用途，不假设 `simple` 能处理中文。

### 向量维度

1. 基线 `vector(1536)`，与 v1.0 保持一致。
2. Embedding 提供方通过 `EMBEDDING_DIM` 参数化；换模型时走 migration：
   - 新增 `embedding_new vector(N)` 列
   - 回填/重算
   - 建 HNSW
   - 切换读写
   - 删除旧列
3. 记录模型名、维度、归一化方式（cosine 需归一化）。
4. HNSW：`USING hnsw (embedding vector_cosine_ops) WITH (m=16, ef_construction=64)`。

## 理由

- 中文分词放在应用侧，避免在 2C4G 上编译/维护 zhparser。
- `pg_trgm` 对中文子串搜索立即可用，成本低。
- 维度迁移是必然事件，提前设计比事后改表好。

## 后果

**正面**

- 中文标题/摘要可搜；语义检索有 HNSW。
- 换 Embedding 有明确迁移路径。

**负面**

- 正文搜索依赖应用侧分词质量。
- 两套检索（trgm + vector）需要分别调优。
- 维度迁移需要重算全部向量，耗时。

## 验证

- `SELECT ... WHERE title ILIKE '%关键词%'` 走 trgm 索引。
- HNSW 查询 `ORDER BY embedding <=> :q LIMIT 10` 可用。
- 插入错误维度时报错可读，迁移脚本可修复。
