# ADR-0001：单机双库与 Schema 隔离

- 状态：Accepted
- 日期：2026-10-20
- 决策人：莫伯

> **Canonical**：本议题「为何如此」以本文为真源；总册 / docs/03 / 整合总览仅保留结论指针，勿复制背景/替代方案/后果长文。

## 背景

预算与规模要求一台 2C4G 主机承载两个网站。最初方案倾向“双 PostgreSQL 容器”，但 2C4G 无法稳定运行两份数据库实例；同时两站需要数据独立、可分别恢复。

## 决策

1. **单 PostgreSQL 实例**（`pgvector/pgvector:pg16`），内存上限 1024MB。
2. **两个数据库**：
   - `db_mobobrain`：`intel` Schema（业务）+ `n8n` Schema（n8n 自身表）
   - `db_archive`：`archive` Schema（个人档案）
3. 每库独立属主账号；应用不使用超级用户；看板使用只读账号。
4. 备份按库分别 `pg_dump -Fc`，可单独恢复。

## 理由

- 内存：单实例约 380MB 常驻，双实例会翻倍。
- 隔离：不同数据库 + Schema + 账号，满足“数据独立”要求。
- 运维：一个容器、一个端口、一套备份/升级流程。
- 恢复：`pg_dump` 按库恢复，故障域小于整机。

## 后果

**正面**

- 成本低、运维简单、备份粒度合适。
- n8n 表与业务表隔离，升级/清理不影响 `intel`。

**负面**

- 单实例是单点；数据库崩溃会影响两站。
- 资源竞争：n8n 大批量任务可能影响看板查询。
- 需要严格 `max_connections` 与连接池配置。

## 替代方案

| 方案 | 结论 |
|---|---|
| 双 PostgreSQL 容器 | 内存不够，否决 |
| 单库多 Schema | 备份/恢复粒度不足，否决 |
| 外部托管 PostgreSQL | 成本/延迟/备案复杂，暂不考虑 |

## 验证

- `docker stats` 中 Postgres <1GB。
- 两库可分别 `pg_dump` / `pg_restore`。
- `user_dashboard_ro` 只能读 `archive`。
- 触发器在 `db_archive` 内正常工作。
