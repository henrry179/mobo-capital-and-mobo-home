# ADR-0002：域名拓扑与公开静态站

- 状态：Accepted（域名与公开站技术待最终确认）
- 日期：2026-10-20
- 决策人：莫伯

## 背景

v1.0 的 Caddyfile 把思源直接反代到网站 A 根路径，且没有 `basic_auth`，导致“核心研究库仅自己可见”无法成立。同时网站 A 需要“部分内容公开 + 核心库私有”。

## 决策

采用 **一个主域名 + 多子域**：

| 子域 | 用途 | 认证 |
|---|---|---|
| `www` | 公开专栏/静态站 | 无 |
| `kb` | 思源知识库 | BasicAuth |
| `n8n` | 自动化后台 | BasicAuth |
| `archive` | 个人档案看板 | BasicAuth + noindex |
| `admin` | 静态操作台 | BasicAuth |

公开站采用 **Astro 静态构建 + Caddy `file_server`**：

1. 思源作为内容源。
2. 本地/CI 通过思源 API 导出 Markdown。
3. Astro 构建 `dist/`，同步到 `/srv/site`。
4. 图片上传 OSS 公开 Bucket，构建时替换链接。
5. 不在服务器上运行 Node 运行时，不增加容器。

## 理由

- 子域避免 n8n/思源的子路径资源、WebSocket、Webhook 问题。
- 静态站内存占用为 0，Caddy 直接托管，最符合 2C4G 约束。
- 公开与私有边界清晰：`www` 无认证，其余全部 BasicAuth。
- 一个域名 + 子域比两个独立域名更省钱，ICP 只需覆盖主域。

## 后果

**正面**

- 安全边界清晰；Caddy 配置简单；证书自动签发。
- 公开站可缓存、可 CDN、可离线构建。

**负面**

- 需要维护一个构建脚本/流程。
- 思源到静态站不是实时发布，需要手动/定时触发。
- 若未来要评论/搜索，需要额外方案（Pagefind 静态搜索优先）。

## 替代方案

| 方案 | 结论 |
|---|---|
| 思源直接公网发布 | 无法做到“公开专栏 + 私有库”分离，否决 |
| Hugo | 可行，但 Astro 组件化更好；待确认 |
| 两个独立域名 | 可行但成本/证书/备案更复杂；非必需 |
| 子路径 `/kb`、`/n8n` | 资源/Webhook 易错，否决 |

## 验证

- `curl -I https://www...` 返回 200。
- `curl -I https://kb...` 未认证返回 401。
- `curl -I https://archive...` 返回 401 + `X-Robots-Tag: noindex`。
- 公开站图片全部来自 OSS 公开 Bucket，无 404。
