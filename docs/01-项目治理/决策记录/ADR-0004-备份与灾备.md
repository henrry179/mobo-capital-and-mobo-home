# ADR-0004：备份与灾备

- 状态：Accepted
- 日期：2026-10-20
- 决策人：莫伯

## 背景

v1.0 提到“每日 03:00 双库与配置异地加密冷备”和“15 分钟裸机恢复”，但没有给出可执行脚本；Compose 中 `alpine:3.20` 也没有安装 `restic`/`pg_dump`。此外，直接备份运行中的 `pg_data` 可能得到不一致的数据库文件。

## 决策

### 备份

1. **数据库**：每日 `pg_dump -Fc` 分别导出 `db_mobobrain`、`db_archive`；`pg_dumpall --globals-only` 导出角色/权限。
2. **文件**：Restic 备份 `mobobrain_data`、`n8n_data`、Caddy 配置、Compose/Caddyfile/脚本。
3. **不备份**：运行中的 `pg_data`（避免不一致）；证书可重新签发。
4. **仓库**：OSS 私有 Bucket `restic-cold-backup/`，同地域内网 Endpoint。
5. **保留**：日 7、周 4、月 6；每周 `restic check`；每月 `--read-data-subset=5%`。
6. **镜像**：自定义 `deploy/backup/Dockerfile`，内置 `restic` + `postgresql16-client` + `bash` + `tzdata`。

### 恢复

- RPO：24 小时。
- RTO：
  - 数据库/配置：≤2 小时。
  - 大文件（100–500GB）：4–24 小时，取决于 OSS 下载带宽。
- 恢复顺序：停应用 → 拉取快照 → 恢复卷 → 单启 Postgres → `pg_restore` → 全栈拉起 → 对账。
- 每季度做一次 staging 恢复演练，记录实际 RTO。

### 救命胶囊

`.env`、`disaster-recovery.sh`、`RESTIC_PASSWORD`、`N8N_ENCRYPTION_KEY` 离线存入 1Password/Bitwarden；不依赖服务器本身。

## 理由

- 逻辑备份保证数据库一致性。
- Restic 提供加密、去重、增量、S3 兼容。
- 文件卷与数据库分开备份，恢复粒度更细。
- 演练才能证明 RTO，而不是纸面承诺。

## 后果

**正面**

- 可单库恢复、可整机恢复、可验证。
- 备份走内网，流量费为 0。

**负面**

- 每日 `pg_dump` 会占用 CPU/IO，需在低峰执行。
- 500GB 文件恢复不可能 15 分钟完成，必须接受分级 RTO。
- Restic 密码丢失 = 备份不可恢复，必须离线保存。

## 验证

- `restic snapshots` 有当日快照。
- staging 恢复后核心表记录数一致。
- `restic check` 无错误。
- `.env`/密码管理器中的 Restic 密码可解锁快照。
