# ADR-0006：安全与鉴权基线

- 状态：Accepted
- 日期：2026-10-20
- 决策人：莫伯

> **Canonical**：本议题「为何如此」以本文为真源；总册 / docs/03 / 整合总览仅保留结论指针，勿复制背景/替代方案/后果长文。

## 背景

网站 B 存储个人隐私数据；网站 A 的核心研究库也应私有。v1.0 的网关配置存在“思源无认证直出”的缺口，且 RAM 子账号使用 `AliyunOSSFullAccess` 权限过大。

## 决策

### 网络

- 安全组仅开放 22（限制来源）、80、443。
- 所有容器仅在 `internal_net`；Caddy 同时接 `edge_net`。
- PostgreSQL 只绑定 `127.0.0.1:5432`，不对公网。
- SSH 仅密钥登录；禁用 root 密码；ufw + fail2ban。

### 鉴权

- `kb/n8n/archive/admin` 全部 Caddy `basic_auth`。
- 密码 20+ 位，Bcrypt cost ≥14，HTTPS 强制。
- 网站 B 加 `X-Robots-Tag: noindex, nofollow, noarchive`、`X-Frame-Options: DENY`。
- 可选第二层：Tailscale/固定 IP 白名单；不默认引入 Authelia（内存成本）。

### 密钥

- `.env` 权限 600；真实密钥不入 Git。
- OSS RAM 子账号只授予两个 Bucket/必要前缀的自定义策略；不用 `AliyunOSSFullAccess`。
- 私有 Bucket：Private + 阻止公共访问；公开 Bucket：只读 + 禁止空 Referer + 关闭 List。
- `.env`、Restic 密码、n8n 加密密钥离线存密码管理器。

### 应用

- 网站 B 数据库账号只读（看板）/按需写入（CLI），不用超级用户。
- n8n 使用独立 Schema/账号；不挂 Docker socket；不安装不可信社区节点。
- 思源保持 `accessAuthCode`，并置于 Caddy BasicAuth 之后。

## 理由

- 单用户场景下 BasicAuth + HTTPS 足够，成本最低。
- 多层防御（网关 + 应用 + 网络 + 密钥）比单一措施可靠。
- 最小权限降低误操作与泄露影响。

## 后果

**正面**

- 后台不裸奔；隐私数据有基本保护。
- 密钥/权限边界清晰。

**负面**

- BasicAuth 无 TOTP；密码泄露即失守，需要强密码 + 监控。
- 多一层 Tailscale 会增加使用复杂度，作为可选项。
- 密钥轮换需要人工操作。

## 验证

- 未认证访问四个后台均 401。
- `ss -lntp` 无 0.0.0.0:5432。
- `.env` 未被 Git 跟踪。
- OSS RAM 策略只允许目标 Bucket。
- 安全头检查通过。
