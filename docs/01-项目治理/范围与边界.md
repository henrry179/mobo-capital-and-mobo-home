# 范围与边界

## 1. 系统边界

```text
[用户浏览器 / CLI]
      │ HTTPS
      ▼
[Caddy 网关] ── mobocapital.com（莫伯资本：公开栏目 + /internal 内网驾驶舱）
      ├──────── mobohome.com（莫伯之家：人生叙事 + 影像 + 藏书馆 + /internal）
      ├──────── kb.*（思源，投研母本）
      ├──────── n8n.*（自动化，#1 情报提纯 / #2 1+3 四端发布）
      ├──────── lab.*（Streamlit 生命体征实验室）
      └──────── admin.*（静态操作台）
      │
      ▼
[单机 Docker 网络 internal_net]
      ├─ PostgreSQL 16 + pgvector（双库四 Schema）
      ├─ 思源笔记
      ├─ n8n
      ├─ Streamlit
      └─ restic-backup
      │
      ▼
[阿里云 OSS 同地域]
      ├─ 公开图床 mobobrain-assets-pub
      └─ 私有桶 mobo-archive-private-hz（photo/ video/ scan_doc/ blotters/ thumbnails/ + restic-cold-backup/）
```

**边界原则**

- 所有公网流量只经 Caddy；数据库、n8n、思源、Streamlit 不直接暴露公网。
- 网站 A 与网站 B 不共享业务表；只共享 PostgreSQL 实例、备份通道与 OSS 桶。
- 网站 B 的原始文件只存 OSS 私有 Bucket；数据库存元数据与索引。
- 网站 A 的实盘底稿只在 `capital` Schema 与 `/internal/*` 出现，公域包物理脱敏后不含私有字段。
- 备份是"数据库逻辑备份 + 文件卷 + 配置"，不是对运行中 `pg_data` 的直接拷贝。

## 2. 范围分层

### MVP（必须，P0）

- 云主机、OSS、双域名、ICP。
- 双库四 Schema 初始化、archive 五模块、intel 采集域、capital 投研域、触发器、索引、账号。
- 六容器编排、Caddy 双主域 + 四子域、BasicAuth、三级可见性。
- 网站 B 看板 + 52 周沙盒；CLI 录入（`upload/read/workout/bio/retro`）。
- 莫伯资本：宏观论点/策略手册/交易复盘录入 + NAV 高水位与回撤熔断 + 宏观与期权终端表。
- n8n 工作流 #1（采集入库 + 高分推思源）与 #2（1+3 四端合成，人工终审）。
- 静态双站门户 + 公私域物理脱敏导出。
- 每日备份 + 灾备/演练脚本 + Smoke Test + 监控与巡检。
- 部署/运维/安全/成本/合规文档。

### P1（上线后 2–4 周）

- 中文全文检索增强（应用侧分词/zhparser）。
- OSS 生命周期与账单审计自动化、资产引用计数与 GC。
- 外部 uptime、告警通知渠道、日志轮转。
- `macro_iv_collector.py` 上线并接宿主机 Cron（双时段采集）。
- 基金治理文档库与合规声明版本化。

### P2（按需）

- 视频缩略图/转码、OCR。
- 移动端快速录入（PWA/Telegram Bot）。
- 多用户/TOTP/SSO、IP 白名单或 Tailscale。
- 更复杂的统计模型（多重检验校正、状态空间模型）。
- 自动群发（需评估平台条款与合规风险）。
- 8C8G 多智能体平台形态（参考 `docs/07-原始资料/原始方案/阿里云云端多智能体网站平台_部署与运营整合方案.docx`）。

## 3. 数据边界

| 数据 | 存放 | 访问 | 保留 |
|---|---|---|---|
| 思源文档/附件 | 主机卷 `mobobrain_data` + 备份 | `kb` BasicAuth | 长期 |
| 文章库/草稿 | `db_mobobrain` | n8n/内网 | 长期 |
| 档案元数据 | `db_archive` | `archive` BasicAuth | 长期 |
| 照片/视频原片 | OSS 私有 Bucket | 签名 URL | 长期/按需归档 |
| 缩略图 | OSS 标准层 `thumbnails/` | 签名 URL | 长期 |
| 公开配图 | OSS 公开 Bucket | 公网 | 长期 |
| 备份 | OSS 私有 `restic-cold-backup/` | Restic 密码 | 日7/周4/月6 |
| 密钥 | `.env` + 密码管理器 | 仅莫伯 | 长期/轮换 |

## 4. 不在范围

- 对外提供 SaaS、多人注册、评论、论坛、社区。
- 自动抓取付费/登录墙内容；遵守来源网站 robots/条款。
- 自动发布到微信/雪球/X；只生成草稿。
- 在服务器上训练大模型；只调用外部 API。
- 在 2C4G 上跑 Elasticsearch、Milvus、完整 OCR 集群。
- 多地域双活；本期为单机 + 异地对象存储备份。

## 5. 变更控制

1. 提出变更：描述背景、影响、替代方案。
2. 评估：范围/成本/风险/迁移难度。
3. 决策：架构级写 ADR；数据库写 migration；安全相关更新基线。
4. 实施：小步提交，更新文档与测试。
5. 验收：更新验收清单与修订记录。

## 6. 验收边界

- “完成”以 `docs/02-需求与验收/验收标准与DoD.md` 为准，不以“代码写完”为准。
- 任何未通过恢复演练的备份，视为未完成。
- 任何未通过未认证 401 检查的后台，视为未完成。
- 任何超过 2,400 元/年的方案，视为未通过。
