# 部署手册

> 目标：在一台阿里云 2 核 4GB / Ubuntu 22.04 或 24.04 主机上，以 Docker Compose 部署双站六容器。
> 对应总册 T-01~T-16。**未完成 ICP 备案前，不要切正式域名对外提供服务。**

## 0. 部署前检查

| 项 | 要求 | 检查命令 |
|---|---|---|
| 主机 | 2C4G，50GB+ SSD，Ubuntu 22.04/24.04 | `lsb_release -a` |
| Docker | Engine 24+，Compose v2 | `docker --version && docker compose version` |
| 域名 | **双主域** `mobocapital.com` + `mobohome.com`，各带 3–4 个子域 | `dig +short mobocapital.com` |
| ICP | 两个主域均需备案（网站 A / 网站 B） | 阿里云备案控制台 |
| OSS | 同地域，双 Bucket | 控制台 |
| 端口 | 80/443 入站；22 限制来源 | 安全组 |
| 备份 | OSS 私有 Bucket + Restic 密码 | 密码管理器 |

> 当前仓库的开发机可能未安装 Docker；这不影响代码交付，但 `docker compose config`、容器启动、集成测试必须在有 Docker 的机器执行。
> 部署顺序与验收口径见根目录 `TASK_STATE.md`（T01–T16）。

## 1. T-01~T-04：采购与基础资源

1. **ECS/轻量应用服务器**：2 核 4GB，Ubuntu 24.04，50GB ESSD；公网带宽按量或 5Mbps。
2. **OSS**：
   - `mobobrain-assets-pub`：公开读，存公开图床/缩略图。
   - `mobo-archive-private-hz`：私有，存档案原片/视频/备份。
   - 同地域（如 `cn-hangzhou`），开启版本控制（私有 Bucket）。
3. **RAM 子账号**：只授予两个 Bucket 的 `oss:PutObject`、`oss:GetObject`、`oss:DeleteObject`、`oss:ListObjects`；不要 `AliyunOSSFullAccess`。
4. **域名**：主域名 + `www`、`kb`、`n8n`、`archive`、`admin` 五条 A/AAAA 记录。
5. **备案**：网站 A 与网站 B 分别提交；备案期间可用 IP + 本地 hosts 做内测，不要开放公网 80。

## 2. T-05：主机初始化

```bash
# 以 root 登录
apt update && apt upgrade -y
timedatectl set-timezone Asia/Shanghai
hostnamectl set-hostname mobo-prod

# 安装 Docker（官方 apt 仓库；按官方文档执行）
# https://docs.docker.com/engine/install/ubuntu/
docker --version
docker compose version

# 创建部署目录
mkdir -p /opt/mobo-stack
```

### 2.1 上传代码

在本地项目根目录打包（排除 `.env`、数据卷、`.git`）：

```bash
tar --exclude='.env' --exclude='deploy/volumes' --exclude='.git' \
    -czf mobo-stack.tar.gz .
scp mobo-stack.tar.gz root@<server-ip>:/opt/
ssh root@<server-ip>
cd /opt && tar -xzf mobo-stack.tar.gz -C /opt/mobo-stack
```

或者用 Git（私有仓库）：

```bash
cd /opt
git clone <your-private-repo> mobo-stack
cd mobo-stack
```

### 2.2 目录与权限

```bash
cd /opt/mobo-stack
mkdir -p deploy/volumes/{caddy_data,caddy_config,caddy_logs,pg_data,mobobrain_data,n8n_data,backup_staging}
chmod 755 deploy/volumes

# Caddy / 思源 / n8n 容器内以 UID 1000 运行，目录需可写
chown -R 1000:1000 deploy/volumes/caddy_data \
  deploy/volumes/caddy_config deploy/volumes/caddy_logs \
  deploy/volumes/mobobrain_data deploy/volumes/n8n_data
chmod 750 deploy/volumes/caddy_data deploy/volumes/caddy_config deploy/volumes/caddy_logs
# pg_data 由 postgres 镜像入口以 root 初始化后降权，保持默认权限
# backup_staging 由 restic 备份容器写入（root）
```

## 3. T-06：环境变量与密钥

```bash
cp .env.example .env
chmod 600 .env
```

逐项替换（v2.1 变量口径：`PG_*` / `ALIYUN_*` / `OSS_*`）：

- `DOMAIN_CAPITAL`、`DOMAIN_HOME`、`DOMAIN_PKM`、`DOMAIN_N8N`、`DOMAIN_LAB`、`DOMAIN_ADMIN`：真实域名。
- `ACME_EMAIL`：真实邮箱。
- `CADDY_ADMIN_PASSWORD_HASH`：**单引号包裹**的 Bcrypt 哈希（同时保护 `/internal/*` 与 `/lab/*`）。
- `PG_SUPER_PASSWORD`、`PG_PASS_MOBOBRAIN`、`PG_PASS_ARCHIVE`、`N8N_DB_PASSWORD`、`DASHBOARD_DB_PASSWORD`、`BACKUP_DB_PASSWORD`：至少 24 位随机。
- `SIYUAN_ACCESS_AUTH_CODE`：思源访问码。
- `N8N_ENCRYPTION_KEY`：32 位以上随机，**必须存密码管理器**。
- `ALIYUN_ACCESS_KEY_ID/ALIYUN_ACCESS_KEY_SECRET`：RAM 子账号 AK/SK。
- `OSS_ENDPOINT`（容器内网）/ `OSS_PUBLIC_ENDPOINT`（宿主机与公网）、`OSS_BUCKET_PUBLIC`、`OSS_BUCKET_PRIVATE`。
- `RESTIC_PASSWORD`：Restic 仓库加密密码，**必须存密码管理器**。
- `WECHAT_APPID/WECHAT_SECRET/WECHAT_DEFAULT_THUMB_MEDIA_ID`：公众号草稿箱直推（可暂留占位）。
- `ALERT_WEBHOOK_URL`：巡检告警推送。
- `LLM_*` / `EMBEDDING_*`：实际服务；维度必须与 `vector(1536)` 一致。

生成哈希与随机值：

```bash
docker run --rm caddy:2.9-alpine caddy hash-password --plaintext '替换为强密码'
openssl rand -base64 32
openssl rand -hex 32
```

> `.env` 中的 `$`（Bcrypt 哈希）必须用单引号包裹，否则 Compose 会做变量插值。不要把 `.env` 提交 Git、发群、写文档。

## 4. T-07：主机加固

```bash
cd /opt/mobo-stack
./deploy/scripts/host-hardening.sh
```

脚本会：

- 创建 4GB Swap，`vm.swappiness=10`。
- 关闭 SSH 密码登录（仅在检测到 `/root/.ssh/authorized_keys` 时；否则跳过）。
- UFW 放行 22/80/443/443udp。
- fail2ban：SSH + Caddy 401。
- Docker 日志轮转、自动安全更新、journald 限额。

**先确认密钥登录可用，再关闭密码登录。** 如 SSH 端口不是 22，先设置 `SSH_PORT=2222`。

## 5. T-08：数据库初始化

```bash
cd /opt/mobo-stack
docker compose config >/dev/null
docker compose up -d postgres
docker compose logs -f postgres
```

看到 `database system is ready to accept connections` 后，验证：

```bash
docker compose exec -T postgres psql -U postgres -d postgres -c '\l'
docker compose exec -T postgres psql -U postgres -d db_archive -c '\dt archive.*'
docker compose exec -T postgres psql -U postgres -d db_mobobrain -c '\dt intel.*'
docker compose exec -T postgres psql -U postgres -d db_mobobrain -c '\dt capital.*'
```

预期：

- 双库 `db_mobobrain`、`db_archive`。
- `db_mobobrain` 三 Schema：`intel`（5 表 + 1 视图）、`capital`（10 表 + 4 视图）、`n8n`。
- `db_archive`：`archive` 8 张表 + 3 视图。
- 触发器 4 个时间线同步 + `trg_auto_calc_nav_on_trade` + 各域 `updated_at`。
- 角色 `user_mobobrain`、`user_archive`、`user_n8n`、`user_dashboard_ro`、`user_backup`。

验证 `capital` 域种子与净值台账：

```bash
docker compose exec -T postgres psql -U postgres -d db_mobobrain \
  -c "SELECT strategy_code, name FROM capital.strategy_playbooks ORDER BY 1;"
docker compose exec -T postgres psql -U postgres -d db_mobobrain \
  -c "SELECT valuation_date, gross_nav, risk_regime_status FROM capital.portfolio_nav_ledger;"
```

> 初始化脚本只在空 `pg_data` 首次启动执行。失败时先看 `docker compose logs postgres`，不要直接删卷；修 SQL 后需重建空卷（生产必须先备份）。

## 7. T-11：DNS 与 HTTPS

1. 在 DNS 添加 A 记录（两个主域各一组，全部指向同一 IP）：
   - `mobocapital.com` / `www.mobocapital.com`
   - `kb.mobocapital.com`（思源）
   - `n8n.mobocapital.com`（自动化）
   - `admin.mobocapital.com`（操作台）
   - `mobohome.com` / `www.mobohome.com`
   - `lab.mobohome.com`（生命体征实验室）
2. 安全组放行 80/443；不要放行 5432/6806/5678/8501。
3. Caddy 自动申请证书；观察：

```bash
docker compose logs -f caddy | grep -Ei 'certificate|acme|error'
```

4. 验证：

```bash
curl -I https://mobocapital.com/            # 期望 200
curl -I https://mobohome.com/                # 期望 200
curl -I https://kb.mobocapital.com/         # 期望 401
curl -I https://n8n.mobocapital.com/        # 期望 401
curl -I https://admin.mobocapital.com/      # 期望 401
curl -I https://lab.mobohome.com/            # 期望 401
curl -I https://mobocapital.com/internal/internal-data.json   # 期望 401
curl -I https://mobocapital.com/data/public-data.json         # 期望 200
```

> 若 80 端口被占用/备案未通过，Caddy 无法完成 HTTP-01；可先用 DNS-01 或暂缓正式域名。不要关闭 HTTPS 强行上线。

## 8. T-12：n8n 初始化

1. 浏览器打开 `https://n8n.mobocapital.com/`，输入 BasicAuth。
2. 创建 owner 账号（邮箱/强密码），立即启用 2FA（如版本支持）。
3. 创建 PostgreSQL 凭证：
   - Host `postgres`，Port `5432`，Database `db_mobobrain`，Schema `n8n`，User `user_n8n`。
4. 导入 `workflows/` 下 JSON：#1 情报提纯、#2 采集评分、#3 “1+3”四端合成；先禁用，手工测试后再启用。
5. 配置 LLM/Embedding 凭证与微信/X 凭证（放 n8n Credentials，不写进工作流 JSON）；不要用生产 Key 做测试。
6. 首次运行工作流，检查 `intel.ingestion_runs` 与 `intel.llm_usage`；工作流 #2 的四端合成结果应落在 `capital.capital_publications`（`PENDING_REVIEW`）。

## 9. T-13：OSS Guard 与首次备份

### 9.1 OSS Guard

在能访问公网 Endpoint 的机器（或服务器）执行：

```bash
cd /opt/mobo-stack
set -a; . ./.env; set +a
python3 -m venv .venv-oss
. .venv-oss/bin/activate
pip install -r deploy/scripts/requirements.txt
DRY_RUN=1 python deploy/scripts/oss_guard_setup.py
python deploy/scripts/oss_guard_setup.py
```

核对：

- 公开 Bucket：公共读、防盗链 `allow_empty=False`、`tmp/` 7 天清理。
- 私有 Bucket：私有、阻止公共访问、4 条生命周期规则。
- `restic-cold-backup/` 不转 Archive。

### 9.2 首次备份

```bash
docker compose exec -T restic-backup /usr/local/bin/run-daily-backup.sh
docker compose exec -T restic-backup restic snapshots --latest 3
```

> 首次备份会初始化 Restic 仓库；确保 OSS Bucket/前缀可写、`RESTIC_PASSWORD` 已存密码管理器。

## 13. 回滚

### 13.1 代码/配置回滚

```bash
cd /opt/mobo-stack
git log --oneline -5
git checkout <previous-commit>
docker compose up -d --build
```

### 13.2 容器回滚（不删数据）

```bash
docker compose down          # 不删卷
docker compose up -d
```

> 不要执行 `docker compose down -v`，除非确认要清空数据库/思源/n8n 数据。

### 13.3 数据库回滚

优先用迁移的回滚脚本；没有回滚脚本时，从最近备份恢复到新库，再切换应用连接。禁止在生产直接 `DROP DATABASE`。

### 13.4 证书/域名回滚

- DNS 改回旧 IP 后等待 TTL。
- Caddy 证书在 `caddy_data` 卷；重装后会自动重签。
- 备案未通过时，关闭 80/443 公网入口，避免违规。
