# 备份与恢复演练

> 目标：证明“备份可用”，而不是“备份任务曾经跑过”。至少每季度一次完整演练，首次上线前必须一次。

## 1. 目标与指标

| 项 | 目标 |
|---|---|
| RPO | 24 小时（每日 03:00） |
| RTO（数据库+配置） | ≤ 2 小时 |
| RTO（文件卷） | 4–24 小时 |
| 备份保留 | 7 日 + 4 周 + 6 月 |
| 恢复演练频率 | 每季度；重大变更后追加 |
| 演练环境 | 生产机（非破坏性）或独立 staging |

## 2. 备份内容

| 内容 | 方式 | 位置 |
|---|---|---|
| `db_mobobrain` | `pg_dump -Fc` | Restic |
| `db_archive` | `pg_dump -Fc` | Restic |
| 角色/权限 | `pg_dumpall --globals-only` | Restic |
| 思源工作区 | 卷文件 | Restic |
| n8n 数据 | 卷文件 | Restic |
| Caddy/备份脚本/初始化 SQL/Compose | 配置目录 | Restic |
| `.env` | **不备份** | 密码管理器 |

## 3. 非破坏性演练（推荐）

### 3.1 前置

- 服务器已安装 `restic`、`psql`、`pg_restore`、`createdb`。
- `127.0.0.1:5432` 可连（Compose 已映射）。
- `.env` 可读；不要在演练中改生产数据。
- 预留至少 5GB 磁盘。

### 3.2 执行

```bash
cd /opt/mobo-stack
./deploy/backup/restore-drill.sh
```

可选：

```bash
RESTORE_TARGET=<snapshot-id> ./deploy/backup/restore-drill.sh
KEEP_STAGING=1 ./deploy/backup/restore-drill.sh
```

### 3.3 脚本做了什么

1. `restic snapshots --tag mobo-daily --latest 1`。
2. `restic restore` 到 `drill-restore/`。
3. 找到最新 `db_mobobrain-*.dump` / `db_archive-*.dump`。
4. 创建 `db_mobobrain_drill` / `db_archive_drill`。
5. `pg_restore` 双库。
6. 对账核心表计数、触发器、周视图。
7. 列出文件快照中的 `mobobrain_data` / `n8n_data` / `config`。
8. 删除演练库与 staging（失败时保留）。

### 3.4 验收标准

- [ ] `restic restore` 成功，无缺失文件。
- [ ] 双库 `pg_restore` 无 fatal error（warning 可接受）。
- [ ] 核心表计数与快照一致（允许生产增量差异）。
- [ ] 4 个时间线触发器存在。
- [ ] `v_weekly_life_analytics` 可查询。
- [ ] 文件快照包含思源/n8n/config。
- [ ] 演练耗时记录。

## 4. 破坏性恢复（真实灾难）

仅在服务器重装/数据卷损坏时执行。

```bash
# 1) 安装 Docker/Compose/restic/postgresql-client/rsync
# 2) 从密码管理器恢复 /opt/mobo-stack/.env（含 RESTIC_PASSWORD）
# 3) 项目根执行
CONFIRM_RESTORE=YES ./deploy/backup/disaster-recovery.sh
```

脚本会停止容器、覆盖数据卷、DROP/重建双库。执行前确认：

- [ ] 已确认没有其他可用副本。
- [ ] 已记录当前故障现象，保留日志。
- [ ] `.env` 的 `N8N_ENCRYPTION_KEY` 与备份时一致。
- [ ] OSS 可访问，Restic 密码正确。
- [ ] 有足够磁盘空间（至少备份体积的 2 倍）。

## 6. 首次演练建议

1. 先只恢复 `db_archive` 到演练库，确认脚本与权限。
2. 再恢复双库，测触发器。
3. 最后测文件快照列表（不覆盖生产卷）。
4. 记录实际下载速度；如果 4GB 文件下载 > 2 小时，考虑提高带宽/预热。

## 7. 恢复后的业务验证

- [ ] 看板周度视图有最近 52 周。
- [ ] 阅读完读事件出现在时间线。
- [ ] 运动记录出现在时间线。
- [ ] 复盘事件出现在时间线。
- [ ] 资产总账数量/容量合理。
- [ ] 思源附件可打开。
- [ ] n8n 工作流可执行，凭证可解密。
- [ ] 新写入一条测试数据，触发器正常，然后删除/回滚。

## 8. 常见失败与处理

见 [`故障排查.md`](故障排查.md) 第 9 节。补充：

| 失败 | 处理 |
|---|---|
| 磁盘不足 | 清理 staging/旧镜像；扩大磁盘 |
| `pg_restore` 权限错误 | 用 postgres 超级用户恢复；角色先存在 |
| 扩展缺失 | 确认 pgvector 镜像；先 `CREATE EXTENSION vector` |
| 文件权限错误 | `chown -R 1000:1000` 思源/n8n 卷 |
| n8n 凭证无法解密 | 恢复原 `N8N_ENCRYPTION_KEY` |
| 恢复后 Caddy 证书丢失 | 自动重签；检查 80/443 与 DNS |
