# 安全基线

> 适用：单机双站、公网 HTTPS、BasicAuth、私有档案、OSS 双 Bucket、n8n 自动化。
> 目标：在没有专职安全团队的情况下，守住“入口、密钥、数据、备份”四条线。

## 1. 信任边界

```text
Internet
  │ 80/443
  ▼
Caddy（TLS + BasicAuth + 安全头）
  ├─ www  → 静态文件（公开）
  ├─ kb   → 思源（认证）
  ├─ n8n  → n8n（认证）
  ├─ archive → Streamlit（认证 + noindex）
  └─ admin → 静态操作台（认证）
        │ internal_net
        ▼
PostgreSQL / 思源 / n8n / 看板
        │ egress_net
        ▼
OSS / LLM / Embedding / RSS
```

  只有 Caddy 暴露 80/443；PostgreSQL/思源/n8n/看板端口不映射公网。
  `internal_net` 为 `internal: true`；需要出网的服务单独加入 `egress_net`。
  宿主机 5432 只绑定 `127.0.0.1`，供 CLI/演练使用。

## 2. 账号与密钥

| 项 | 基线 |
|   |   |
| 服务器 | 禁用 root 密码登录；仅密钥；`PermitRootLogin prohibit password` |
| 数据库 | 应用账号非超级用户；密码 ≥24 位随机；每库独立 |
| Caddy | BasicAuth Bcrypt；密码 ≥16 位；不与其他系统复用 |
| n8n | owner 强密码 + 2FA；加密密钥 ≥32 位 |
| OSS | RAM 子账号最小权限；AK 不写代码；定期轮换 |
| Restic | 独立强密码；存密码管理器；`restic key` 轮换 |
| `.env` | `chmod 600`；不进 Git、不进聊天、不进截图 |

### 2.1 密钥清单

见 [`密钥与凭据清单`](../06 合规与成本/密钥与凭据清单.md)。原则：

  一个密钥只做一件事。
  生产/测试分离。
  泄露后先禁用/轮换，再排查日志。
  不把密钥写进 `docker compose.yml`、Caddyfile、n8n 工作流 JSON。

## 3. 网络与主机

### 3.1 安全组/UFW

  入站：22（限制来源 IP）、80、443、443/udp。
  出站：443（OSS/LLM/RSS）、DNS、NTP；按需限制。
  禁止：5432、6806、5678、8501 对公网。

### 3.2 SSH

```bash
# 只允许密钥
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin prohibit password
MaxAuthTries 5
```

  使用非默认端口（可选，但需同步 UFW/安全组）。
  fail2ban `sshd`：5 次失败封 2 小时。
  不在服务器保存私钥明文；使用 ssh agent/硬件密钥。

### 3.3 主机

  自动安全更新：`unattended upgrades`。
  时区/NTP：`chrony`。
  Docker 日志轮转：10MB × 3。
  journald：200MB 上限。
  4GB Swap，`vm.swappiness=10`。
  定期 `apt upgrade`，内核更新后重启。

## 4. Caddy / HTTPS

  强制 HTTPS；HSTS `max age=31536000; includeSubDomains`。
  安全头：`X Content Type Options`、`X Frame Options: DENY`、`Referrer Policy`、`Permissions Policy`、CSP。
  后台统一 `X Robots Tag: noindex, nofollow, noarchive`。
  BasicAuth 只保护入口；数据库/应用仍需自己的认证。
  Caddy 访问日志写 `deploy/volumes/caddy_logs/access.log`，fail2ban 监控 401。
  证书自动续期；监控剩余 <14 天。

### 4.1 BasicAuth 注意

  Bcrypt 哈希中的 `$` 在 `.env` 必须单引号包裹。
  不要在 URL 中传递用户名/密码给第三方监控。
  定期更换密码；更换后 `docker compose up  d caddy`。
  BasicAuth 不是多用户系统：所有后台共享一个入口账号；需要审计时建独立反代/SSO（P2）。

## 5. 数据库

  `postgres` 超级用户只用于初始化/灾备；应用使用 `user_*`。
  `REVOKE ALL ON DATABASE ... FROM PUBLIC`。
  看板只读 `user_dashboard_ro`；备份只读 `user_backup`。
  不在公网暴露 5432；CLI 通过 SSH 隧道/本机。
  开启 `pg_stat_statements`（可选）做慢查询审计。
  备份文件 `chmod 600`；Restic 加密。
  定期检查角色权限：
  ```sql
  SELECT rolname, rolsuper, rolcreatedb, rolcreaterole, rolcanlogin
  FROM pg_roles WHERE rolname LIKE 'user_%';
  ```

## 6. OSS

| Bucket | ACL | 访问 | 规则 |
|   |   |   |   |
| 公开图床 | 公共读 | 仅 `thumbnails/`、公开图片；防盗链 | `tmp/` 7 天清理 |
| 私有档案 | 私有 | 签名 URL（1h） | 4 条生命周期；禁止公共访问 |

  公开 Bucket 不要放身份证/医疗/合同原片。
  私有 Bucket 开启“阻止公共访问”；RAM 只授权必要前缀。
  防盗链 `allow_empty=False`；白名单只含正式域名。
  不在前端直传 AK/SK；上传走 CLI/后端。
  签名 URL 短有效期；不要长期缓存。

## 7. n8n

  独立子域 + BasicAuth；不要暴露 `/webhook/` 无认证。
  owner 账号 2FA；凭证使用 n8n 加密存储。
  工作流只写 `DRAFT`，发布由人审核。
  限制执行数据保留 7 天；避免磁盘/内存膨胀。
  外部 Webhook 如必须：独立子域 + Header Token + IP 白名单 + 速率限制。
  定期导出工作流 JSON 到仓库（不含凭证）。

## 8. 思源

  访问码强随机；Caddy BasicAuth 为第一层。
  工作区卷不进 Git；备份加密。
  不安装来源不明的插件/主题。
  定期导出重要文档为 Markdown/PDF 冷备。

## 9. 日志与审计

保留：

  Caddy access log（30 天，轮转 5 份）。
  Docker 日志（10MB × 3/容器）。
  PostgreSQL 慢查询/连接（按需）。
  n8n 执行记录（7 天）。
  备份日志（30 天）。

审计：

  每周看 401 暴破、5xx、SSH 失败。
  每月看角色/权限、OSS ACL、生命周期。
  每季度看密钥轮换、恢复演练。

## 10. 隐私与数据分类

  `PUBLIC`：公开文章/图床。
  `RESTRICTED`：可分享给特定人，但不公开。
  `PRIVATE`：个人档案默认。
  `VAULT`：医疗/证件/合同等高敏；仅本人，禁止公网直链。

详见 [`隐私与数据分类`](../06 合规与成本/隐私与数据分类.md)。

## 10.1 三级可见性与物理脱敏（红线四）

网站 A 的内容分级由数据库字段 `visibility` 决定，**不依赖前端隐藏**：

| 级别 | 含义 | 出口 |
|   |   |   |
| `PUBLIC` | 可公开 | `sites/mobocapital/data/public data.json` |
| `LP_PROSPECT` | 准投资人可见 | 同上（仍剔除私有字段） |
| `INTERNAL` | 内网驾驶舱 | `sites/mobocapital/internal/internal data.json`，仅 `/internal/*` + BasicAuth |

强制规则：

1. 导出公域包时**物理删除**：`private_blotter_oss_key`、`signed_blotter_url`、`private_attachment_oss_key`、`oss_object_key`、`oss_thumbnail_key`、`signed_url` 及任何 `access_key*`/`password`/`secret` 字段。
2. 导出公域包时**物理剔除** `visibility='INTERNAL'` 记录；莫伯之家同时剔除 `is_sensitive=TRUE` 与 `privacy ∈ {PRIVATE, VAULT}`。
3. 写盘前执行自检（`exporters.audit_payload()`），不通过直接抛错、不落盘。
4. `internal/` 目录不得出现在 `data/` 下；Caddy 对 `/internal/*` 强制 `basic_auth` + `no store` + `noindex`。
5. 每次发布前跑 `pytest services/mobo cli/tests/test_exporters.py`，并对线上公域 JSON 做 `grep` 巡检。

## 10.2 内容合规（红线五）

  境内平台（微信公众号、雪球）版本必须脱敏具体买卖点位、去除收益承诺、附免责声明。
  所有发布经 HITL 人工终审（`capital_publications.publish_status` 状态机）。
  `INTERNAL` / `VAULT` 数据禁止送入 LLM 与第三方发布接口。
  详细检查清单见 [`证券与自媒体合规`](../06 合规与成本/证券与自媒体合规.md)。

## 11. 事件响应

1. **发现**：监控/用户/日志。
2. **止血**：封 IP、禁用密钥、停工作流、关闭入口。
3. **取证**：保留日志/容器状态/数据库连接；不要立刻删容器。
4. **恢复**：轮换密钥、修补、从干净备份恢复。
5. **复盘**：24–48 小时内记录时间线、根因、改进项。
6. **通知**：如涉及个人信息泄露，按法规/备案要求评估通知义务。
