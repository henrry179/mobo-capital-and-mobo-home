# 监控告警

> 目标：在用户感知前发现“站点不可用、证书过期、磁盘打满、备份失败、数据库连接耗尽、成本异常”。

## 1. 监控分层

| 层 | 指标 | 工具 | 频率 |
|---|---|---|---|
| 可用性 | 5 个 HTTPS 入口状态码/延迟 | UptimeRobot、阿里云拨测 | 1–5 分钟 |
| 主机 | CPU、内存、磁盘、网络、负载 | 阿里云云监控、`node_exporter`（可选） | 1 分钟 |
| 容器 | running/healthy、重启次数、内存 | `docker compose ps`、cAdvisor（可选） | 5 分钟 |
| 数据库 | 连接数、库大小、慢查询、复制（无） | PostgreSQL 查询、`pg_stat_statements` | 5–15 分钟 |
| 业务 | 采集成功/失败、文章增量、LLM 成本 | n8n + `intel.ingestion_runs` | 每次运行 |
| 备份 | 快照时间、校验结果、OSS 容量 | Restic + OSS 控制台 | 每日 |
| 安全 | 401 暴破、SSH 失败、异常登录 | fail2ban、Caddy 日志 | 实时 |

## 2. 可用性检查

| 名称 | URL | 期望 |
|---|---|---|
| 公开站 | `https://www.example.com/` | 200 |
| 知识库 | `https://kb.example.com/` | 401（未认证） |
| 自动化 | `https://n8n.example.com/` | 401 |
| 档案看板 | `https://archive.example.com/` | 401 + `noindex` |
| 操作台 | `https://admin.example.com/` | 401 |

> 不要把 BasicAuth 凭证放进第三方监控的 URL；监控只看 401。若需要登录后健康检查，用服务器本地 curl + BasicAuth，且凭证从环境变量读取。

```bash
# 服务器本地带认证检查（示例，不要在命令行历史留密码）
curl -fsS -u "$CADDY_ADMIN_USER:$CADDY_ADMIN_PASSWORD" https://archive.example.com/_stcore/health
```

## 3. 告警阈值

| 告警 | 条件 | 级别 | 动作 |
|---|---|---|---|
| 站点不可用 | 连续 3 次非期望状态码/超时 | P1 | 查 Caddy/容器/证书 |
| 证书剩余 | < 14 天 | P1 | 查 80/443、Caddy 日志 |
| 磁盘 | > 80% | P1 | 清日志/镜像/扩容 |
| 内存 | > 90% 持续 10 分钟 | P2 | 查 n8n/看板，重启 |
| Swap | > 2GB 持续 30 分钟 | P2 | 降并发/加内存 |
| 容器重启 | 10 分钟内 ≥3 次 | P2 | 看日志/健康检查 |
| 数据库连接 | > 35 / 40 | P2 | 查泄漏/长事务 |
| 备份失败 | 24h 无新快照 | P1 | 手工触发/查 OSS |
| OSS 成本 | 日环比 > 30% | P2 | 查请求/流量/生命周期 |
| n8n 失败 | 连续 2 次 FAILED | P2 | 查凭证/额度/JSON |
| 401 暴破 | 10 分钟 > 100 次 | P2 | fail2ban/封 IP |

## 4. 阿里云云监控

建议配置：

- CPU 使用率 > 80% 持续 5 分钟。
- 内存使用率 > 85% 持续 5 分钟。
- 磁盘使用率 > 80%。
- 公网出带宽持续打满。
- 实例宕机/重启。

通知：短信 + 邮件；P1 同时电话。

## 5. UptimeRobot / 拨测

- 5 个 HTTPS 监控，间隔 5 分钟。
- 关键字（可选）：`www` 页面包含“莫伯”；其他不检查关键字。
- 关闭“跟随重定向”或明确允许 301→200。
- 状态页不公开档案入口。

## 6. 日志监控

### 6.1 Caddy

```bash
# 5xx
grep '"status":5' deploy/volumes/caddy_logs/access.log | tail -n 50

# 401 暴破
grep '"status":401' deploy/volumes/caddy_logs/access.log | tail -n 100

# 证书
docker compose logs caddy | grep -Ei 'certificate|acme|error'
```

### 6.2 容器

```bash
docker compose ps
docker events --filter 'type=container' --filter 'event=die' --since 1h
docker inspect -f '{{.Name}} restarts={{.RestartCount}}' $(docker compose ps -q)
```

### 6.3 数据库

```sql
-- 连接数
SELECT datname, count(*) FROM pg_stat_activity GROUP BY 1;

-- 长事务（>5 分钟）
SELECT pid, now()-xact_start AS age, query
FROM pg_stat_activity
WHERE xact_start IS NOT NULL AND now()-xact_start > interval '5 minutes';

-- 库大小
SELECT datname, pg_size_pretty(pg_database_size(datname))
FROM pg_database WHERE datname LIKE 'db_%';

-- 表膨胀/死元组
SELECT relname, n_dead_tup, last_autovacuum
FROM pg_stat_user_tables
ORDER BY n_dead_tup DESC LIMIT 10;

-- 慢查询（需 pg_stat_statements）
SELECT calls, mean_exec_time, query
FROM pg_stat_statements ORDER BY mean_exec_time DESC LIMIT 10;
```

### 6.4 业务

```sql
-- 最近采集运行
SELECT workflow_name, status, started_at, finished_at,
       items_fetched, items_new, items_scored, items_synced, error_message
FROM intel.ingestion_runs ORDER BY started_at DESC LIMIT 10;

-- 24h LLM 成本
SELECT model, sum(cost_usd) usd, sum(prompt_tokens+completion_tokens) tokens
FROM intel.llm_usage
WHERE created_at >= NOW() - INTERVAL '24 hours'
GROUP BY model;

-- 时间线增长
SELECT date_trunc('day', created_at) d, count(*)
FROM archive.timeline_events
WHERE created_at >= NOW() - INTERVAL '14 days'
GROUP BY 1 ORDER BY 1;
```

## 7. 备份监控

```bash
# 最新快照时间（人工）
docker compose exec -T restic-backup restic snapshots --latest 1

# 备份日志
docker compose logs --tail=100 restic-backup

# 本地 staging
ls -lh deploy/volumes/backup_staging/dumps | tail
```

建议在 UptimeRobot 之外增加一个“每日备份心跳”：备份脚本成功后写 `deploy/volumes/backup_staging/last_success`，由外部脚本检查时间戳 > 26h 告警。当前脚本可扩展：

```bash
date -Iseconds > /backup/last_success
```

## 8. 告警降噪

- 同一故障只发一次 P1，恢复时发恢复通知。
- 维护窗口提前静音。
- 401 暴破按 IP 聚合并自动封禁，不逐条通知。
- 磁盘/成本按日汇总，不按分钟重复。

## 9. 值班交接

- P1：先恢复服务，再定位根因；保留现场日志。
- P2：当日处理；记录到变更日志。
- 所有 P1 需在 48 小时内补事故复盘（时间线、根因、改进项）。
