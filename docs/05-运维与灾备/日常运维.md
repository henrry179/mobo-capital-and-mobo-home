# 日常运维

> 目标：用最少的命令保持六容器稳定；所有异常都能定位到“容器 / 数据库 / 证书 / 磁盘 / 外部 API”之一。

## 1. 每日检查（5 分钟）

```bash
cd /opt/mobo-stack

# 容器状态
docker compose ps

# 资源
docker stats --no-stream
free -m
df -h /

# 最近错误
docker compose logs --since=24h --tail=100 caddy archive-dashboard mobobrain-n8n postgres \
  | grep -Ei 'error|fatal|panic|failed' || true

# 备份
docker compose logs --tail=50 restic-backup
docker compose exec -T restic-backup restic snapshots --latest 1
```

### 每日判读

| 指标 | 正常 | 处理 |
|---|---|---|
| 容器 | 全部 running，关键服务 healthy | 重启/看日志 |
| 内存 | 总使用 < 3.2GB，Swap 使用 < 1GB | 降 n8n 并发/清缓存 |
| 磁盘 | 使用 < 70% | 清 Docker 日志/旧镜像/备份 staging |
| 备份 | 当日快照存在 | 手工触发并查 OSS |
| 证书 | 剩余 > 14 天 | Caddy 自动续期；检查 80 端口 |

## 2. 每周检查

```bash
# Restic 元数据校验
docker compose exec -T restic-backup restic check

# 数据库大小/连接
docker compose exec -T postgres psql -U postgres -d db_archive -c "
SELECT pg_size_pretty(pg_database_size('db_archive')) AS archive_size,
       (SELECT count(*) FROM pg_stat_activity WHERE datname='db_archive') AS conns;"
docker compose exec -T postgres psql -U postgres -d db_mobobrain -c "
SELECT pg_size_pretty(pg_database_size('db_mobobrain')) AS mobobrain_size,
       (SELECT count(*) FROM pg_stat_activity WHERE datname='db_mobobrain') AS conns;"

# 时间线/资产增长
docker compose exec -T postgres psql -U postgres -d db_archive -c "
SELECT 'timeline' AS t, count(*) FROM archive.timeline_events
UNION ALL SELECT 'assets', count(*) FROM archive.archive_assets
UNION ALL SELECT 'reading', count(*) FROM archive.reading_items
UNION ALL SELECT 'workouts', count(*) FROM archive.fitness_workouts;"

# Docker 磁盘
docker system df
```

## 4. 常用操作

### 4.1 重启单个服务

```bash
docker compose restart caddy
docker compose restart archive-dashboard
docker compose up -d --force-recreate mobobrain-n8n
```

### 4.2 查看实时日志

```bash
docker compose logs -f --tail=200 caddy
docker compose logs -f --tail=200 postgres
docker compose logs -f --tail=200 archive-dashboard
```

### 4.3 进入容器

```bash
docker compose exec postgres psql -U postgres -d db_archive
docker compose exec caddy sh
docker compose exec archive-dashboard sh
```

### 4.4 更新镜像（谨慎）

```bash
# 1) 备份
docker compose exec -T restic-backup /usr/local/bin/run-daily-backup.sh

# 2) 拉取固定 tag（不要长期用 latest）
docker compose pull caddy postgres mobobrain-pkm mobobrain-n8n

# 3) 重建
docker compose up -d

# 4) 验证
./deploy/scripts/smoke-test.sh
```

> 生产建议把 `latest` 改为具体版本 tag，并在 staging 先验证。思源/n8n 大版本升级前备份卷+数据库。

### 4.5 轮换密钥

| 密钥 | 步骤 |
|---|---|
| Caddy 密码 | 生成新哈希 → 改 `.env` → `docker compose up -d caddy` |
| 数据库密码 | `ALTER ROLE ... PASSWORD` → 改 `.env` → 重启对应服务 |
| OSS AK/SK | 新建 RAM 子账号 → 改 `.env` → 重启 n8n/看板/备份 → 禁用旧 AK |
| Restic 密码 | `restic key add` → 验证 → `restic key remove`；同步密码管理器 |
| n8n 加密密钥 | **不能直接改**；需导出/重新录入凭证，或保持原密钥 |

### 4.6 清理备份 staging

```bash
# 只清 2 天前的本地 dump；Restic 快照不受影响
find deploy/volumes/backup_staging/dumps -type f -mtime +2 -delete
```

### 4.7 查看 Caddy 401 暴破

```bash
tail -n 200 deploy/volumes/caddy_logs/access.log | grep '"status":401' | tail
docker compose exec caddy fail2ban-client status 2>/dev/null || true
# fail2ban 在宿主机
fail2ban-client status caddy-401
```

## 5. 容量管理

| 资源 | 阈值 | 动作 |
|---|---|---|
| 根磁盘 > 70% | 警告 | 清 Docker 日志、旧镜像、staging |
| 根磁盘 > 85% | 严重 | 扩容/迁移 OSS、清 pg 备份 |
| `pg_data` > 20GB | 关注 | 归档旧数据/分区 |
| OSS 标准层 > 80% 预算 | 关注 | 核对生命周期规则 |
| n8n 执行记录 > 10 万 | 清理 | 调整 `EXECUTIONS_DATA_MAX_AGE` |
